# 로또 6/45 규칙과 추첨 일정

## 게임

1부터 45까지의 번호 중 6개를 고른다. 추첨에서 6개의 당첨번호와 1개의 보너스 번호가 나온다.

## 등위 판정

| 등위 | 조건 |
|------|------|
| 1등 | 당첨번호 6개 일치 |
| 2등 | 당첨번호 5개 + 보너스 번호 일치 |
| 3등 | 당첨번호 5개 일치 |
| 4등 | 당첨번호 4개 일치 |
| 5등 | 당첨번호 3개 일치 |

보너스 번호는 **2등 판정에만** 쓰인다. 3등은 5개를 맞추되 보너스가 아닌 경우다. 통계 페이지에서 "보너스 번호 포함/제외" 옵션을 주는 이유가 여기 있다 — 보너스는 당첨번호와 성격이 다르다.

> 등위별 당첨금 배분 비율은 이 위키에 적지 않는다. 회차마다 총 판매금액에 따라 달라지고, 우리 데이터 소스에 없다. UI 는 수집된 실제 금액만 표시한다.

## 추첨 일정

**매주 토요일 20:35~20:45 KST** 에 추첨한다. 워커의 `lotto` 잡이 21:00 에 도는 이유다 — 결과가 소스에 반영될 시간을 준다 ([[worker-jobs]]).

**사용자 노출 문구 (002 R22).** 가이드 등 화면에서는 "매주 토요일 **오후 8시 35분경**에 추첨" 으로 쓴다(방송 시작 시각 기준). "OO시 OO분" 자리표시자나 "20:45" 같은 24시간 표기를 그대로 노출하지 않는다 — 40대+ 가독성을 위해 "오후 8시 35분경" 을 표준으로 한다. 추첨 종료 시각은 회차마다 달라 "경" 을 붙인다.

코드상 크론: `CronTrigger(day_of_week="sat", hour=21, minute=0, timezone=KST)` (`backend/app/scheduler.py:71`)

다음 추첨까지의 D-day 는 프론트에서 계산한다. 서버 시각이 아니라 **KST 기준**으로 계산해야 한다. 사용자의 브라우저 타임존이 무엇이든 로또 추첨은 한국 시간에 일어난다.

## 번호 볼 5구간 색상

동행복권 공식 규칙이다. 다른 로또 사이트도 전부 이 규칙을 쓰므로, 사용자는 색만 보고 구간을 안다.

| 구간 | 색 |
|------|-----|
| 1~10 | 노랑 |
| 11~20 | 파랑 |
| 21~30 | 빨강 |
| 31~40 | 회색 |
| 41~45 | 초록 |

기존 구현 (`frontend/src/components/LottoBall.jsx:1-7`) 은 `range-1`~`range-5` 클래스로 이 매핑을 표현한다. 신규 프론트도 같은 경계를 쓴다.

**시안(`docs/raw/메인샘플.png`)의 볼 색상은 이 규칙과 어긋난다.** 시안을 따르지 않는다. 근거는 [[0009-official-ball-colors-over-mockup]], 구현 토큰은 [[design-tokens]].

**색만으로 구간을 전달하지 않는다.** 색각 이상 사용자에게 빨강과 초록은 구분되지 않는다. 볼에는 항상 숫자가 있고, `aria-label` 에 구간을 명시한다 ([[accessibility]]).

## 데이터 저장 규약

당첨번호 6개는 **항상 오름차순**으로 저장한다. `lotto_draw` 의 `CHECK` 제약이 강제한다 ([[db-schema]]). 추첨 순서는 보존하지 않는다 — 어차피 조합이고, 순서를 보존하면 중복 판정이 복잡해진다.

보너스는 별도 컬럼이다. `num1..num6` 에 섞지 않는다.

## 확률에 대하여

45개 중 6개를 고르는 조합의 수는 8,145,060 이다. 이것은 **게임 규칙에서 나오는 사실**이므로 서술해도 된다.

서술하면 안 되는 것은 "이 조합의 당첨 확률" 이나 "이 번호가 나올 가능성" 이다. 모든 조합의 확률은 같다. 과거 통계는 그것을 바꾸지 않는다. 자세한 규약은 [[forbidden-expressions]].
