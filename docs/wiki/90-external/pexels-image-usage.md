# Pexels 이미지 — 라이선스 사실과 사용 방식

002 개편에서 상세페이지(가이드 등)를 풍부하게 만들기 위해 이미지가 필요하다. 사용자가 루트가 아닌 `frontend/.env_frontend` 에 `PEXELS_API_KEY` 를 넣어 두었다. 이 페이지는 **라이선스 사실**과 **어떻게 쓰기로 했는지**를 기록한다.

> **법적 판단은 사용자 몫이다.** 아래는 조사한 사실이며, "이 사이트에 이 이미지를 써도 되는가" 의 최종 판단은 사용자가 한다.

## Pexels License 요지 (사실)

출처: [pexels.com/license](https://www.pexels.com/license/) (조사 시점 기준. 정책은 바뀔 수 있으니 사용 전 재확인).

**허용**

- 무료. 상업·비상업 모두 사용 가능.
- 출처 표기(attribution) **의무 아님**(권장은 함).
- 수정·편집 가능.

**제한 (금지)**

- 사진·영상을 **다른 스톡/배경화면 플랫폼에서 그대로 재판매·재배포** 금지. (우리는 사이트 삽화로 쓰는 것이라 해당 없음)
- **식별 가능한 인물**을 불쾌하거나 부정적인 맥락으로 묘사 금지.
- 사진 속 **인물·상표가 특정 상품/서비스를 추천하는 것처럼 암시** 금지.
- 식별 가능한 **인물·사유재산**이 담긴 이미지는 상업적 사용 시 별도 초상권·재산권(모델/프로퍼티 릴리스) 이슈가 있을 수 있음.

## 우리의 사용 방식 (결정)

### 빌드타임 큐레이션

런타임에 브라우저나 서버가 Pexels API 를 호출하지 않는다. **개발/빌드 시점에 사람이 이미지를 골라 `frontend/public/` 에 내려받아 커밋**한다. 근거는 [[0011-build-time-image-curation]].

- `PEXELS_API_KEY` 는 **서버 전용**이다 — `NEXT_PUBLIC_` 을 붙이지 않는다. 키가 브라우저 번들에 노출되면 안 된다([[env-vars]]).
- `next/image` 미사용(현행 `unoptimized`)과 정합. `<picture>`/`<img>` + `width`/`height` 명시로 CLS 를 막는다([[responsive-rules]]).

### 인물 배제 방침

**실제 사람이 담긴 사진은 쓰지 않는다.** 초상권·모델 릴리스 위험을 원천 차단하고, 로또 맥락에서 인물 사진은 오히려 사행성 인상을 줄 수 있다. 오브젝트·추상 이미지(공, 동전, 종이, 추상 배경)만 고른다.

### 일러스트 우선, 사진은 대안

이 사이트의 시각 언어는 브랜드 팔레트 플랫 일러스트(SVG)로 통일돼 있다. 가이드 상세 이미지도 **AI 생성 일러스트를 1순위**로 하고(프롬프트·저장경로: [`002-이미지제작요청서.md`](../../raw/002-이미지제작요청서.md)), Pexels 실사는 꼭 필요할 때의 대안으로 둔다. **한 페이지 안에서 사진과 일러스트를 섞지 않는다**(일관성 R35).

### 이미지에도 적용되는 규칙

- 이미지에 당첨 확률·고확률·1등 예측·당첨 보장 같은 문구/암시를 넣지 않는다([[forbidden-expressions]]).
- 볼이 나오면 동행복권 공식 5구간 색을 따른다([[lotto-rules]]).
- 최종본은 **사용자가 검수**한 뒤 반영한다.
