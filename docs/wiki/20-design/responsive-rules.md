# 반응형 규약

이 페이지는 작업지시서 5.3 을 정본으로 삼는다. 시안(`docs/raw/메인샘플.png`)은 **데스크톱 라이트 화면만** 보여준다. 모바일 레이아웃은 시안에 없으므로 아래 규약이 유일한 사양이다.

로또 정보 검색 트래픽의 다수가 모바일이다. 따라서 **mobile-first 로 CSS 를 작성한다** — 기본 스타일이 모바일이고, `min-width` 미디어쿼리로 위 단계를 덧입힌다. `max-width` 로 모바일을 예외 처리하지 않는다.

색·간격 토큰은 [[design-tokens]], 각 컴포넌트가 단별로 어떻게 바뀌는지의 세부는 [[components]], 저시력·키보드 관점의 반응형 요구는 [[accessibility]] 를 함께 본다.

## 브레이크포인트 3단

경계는 세 개뿐이다. 세밀한 단을 늘리지 않는다.

- **~639px — 모바일.** 기본(미디어쿼리 없는) 스타일.
- **640~1023px — 태블릿.** `@media (min-width: 640px)`.
- **1024px~ — 데스크톱.** `@media (min-width: 1024px)`. 시안 그대로.

```css
/* mobile-first: 기본 = 모바일 */
.tiles { grid-template-columns: repeat(3, 1fr); }      /* 3×2 */

@media (min-width: 640px) {  /* 태블릿 */
  .home { grid-template-columns: repeat(2, 1fr); }
}
@media (min-width: 1024px) { /* 데스크톱 = 시안 */
  .tiles { grid-template-columns: repeat(6, 1fr); }
}
```

## 홈 7개 섹션의 단별 전환

홈 레이아웃 순서는 고정이다(5.1 · 초안 6.1): 히어로 → 아이콘 6타일 → [최신 회차 결과 | 다음 추첨 D-day | 복권 뉴스] 3분할 → 주요 통계 4카드 → 오늘의 추천번호 캐러셀 → 로또 가이드 5카드 → 푸터. 순서는 어느 단에서도 바뀌지 않는다. 바뀌는 것은 열 수와 몇몇 요소의 형태다.

> **예외 — 새 메인 시안 `/v2`.** 이 순서 규칙은 운영 홈(`/`)에 적용된다. 비교용 시안인 `/v2` 는 정보 구조를 재구성하며(사용자 승인 2026-08-12), 그 구성은 [[home-v2-concept]] 가 정본이다. **두 안 중 하나가 채택되면 이 절을 채택안 기준으로 갱신하고 예외 표기를 지운다.** 그 전까지 두 문서가 서로 다른 순서를 말하는 것은 의도된 상태다.
>
> 다만 시안에도 그대로 적용되는 것: 브레이크포인트 3단, mobile-first, 터치 타겟 44×44px, CLS 방지, `body` 가로 스크롤 금지, `prefers-reduced-motion`.

**1. 히어로.** 데스크톱은 좌측 텍스트 + 우측 복권기계 일러스트 2단. 모바일에서는 일러스트를 숨기거나 축소하고 텍스트·CTA 만 전폭으로 세운다. CTA 버튼은 002 개편으로 **2개**다 — "AI 번호 조합 추천"(1), "꿈으로 번호찾기"(2). 모바일에서 세로로 쌓고 각 버튼을 전폭으로 만든다.

**2. 아이콘 6타일.** 데스크톱 6열 1행. 태블릿·모바일 모두 **3×2 그리드**. 연금복권 타일의 "준비중" 배지는 모든 단에서 유지한다.

**3. 3분할(결과 · D-day · 뉴스).** 데스크톱 3열. 태블릿은 최신 회차 결과를 전폭으로 놓고 그 아래 [D-day | 뉴스] 2열. 모바일은 세로 스택 — 결과 → D-day → 뉴스 순.

**4. 주요 통계 4카드.** 데스크톱 4열(많이 나온 TOP5 · 안 나온 TOP5 · 번호 출현 빈도 · 패턴 분석). 태블릿 2열. 모바일 1열. 막대차트는 모바일에서도 45개를 그대로 그린다(아래 "차트 축약" — 축약 규칙은 폐기됐다).

**5. 오늘의 추천번호 캐러셀.** 데스크톱은 5장 중 여러 장이 한 줄에 보이고 좌우 화살표로 넘긴다. **모바일은 002 개편으로 가로 스크롤을 쓰지 않고 세로 1열 스택으로 죽 잇는다**(R12) — 옆으로 숨은 카드는 40대+ 사용자에게 발견성이 낮다. 좌우 화살표는 데스크톱에서만 렌더한다. 캐러셀 사양은 [[components]].

**6. 로또 가이드 5카드.** 데스크톱은 5열(파스텔 카드). 태블릿 2~3열. 모바일 1열.

**7. 푸터.** 데스크톱은 다열 링크 그룹. 모바일은 링크 그룹을 세로로 접는다(아코디언 또는 스택).

**헤더는 섹션이 아니지만 함께 전환된다.** 데스크톱은 가로 nav(로또·번호통계·번호추천·꿈해몽·뉴스·가이드) + 검색 입력 + 다크 토글. 모바일은 nav 를 **햄버거 드로어**로, 검색은 **아이콘 → 전체화면 오버레이**로 접는다. 헤더 컴포넌트 사양은 [[components]].

## 터치 타겟 최소 44×44px

번호 볼, 캐러셀 좌우 화살표, "다시 생성" 버튼, 햄버거·검색 아이콘, nav 링크 — 손가락으로 누르는 모든 것은 최소 44×44px 히트 영역을 가진다.

번호 볼은 모바일에서 지름을 최소 36px 로 두되, 주변 패딩으로 히트 영역을 44px 까지 넓힌다. 시각 크기와 클릭 영역을 분리한다.

```css
.ball-hit {              /* 44px 히트 영역 */
  display: inline-grid;
  place-items: center;
  min-width: 44px;
  min-height: 44px;
}
.ball { width: 36px; height: 36px; }  /* 시각 크기는 별도 */
```

## 차트 축약 (모바일) — **폐기. 지금은 45개를 그대로 그린다**

> ⚠ 이 절은 오랫동안 "모바일은 상위 5개 막대로 축약한다" 고 적어 왔지만 **코드는 한 번도 그렇게 동작한 적이 없다.** 홈의 차트는 처음부터 45개를 컨테이너 폭에 맞춰 그렸다(`FrequencyChart` 의 `fit` 모드). 2026-08-21 에 확인하고 문서를 구현에 맞춘다.

축약 규칙의 근거는 "45개 막대는 모바일 폭에서 가독성이 없다" 였다. 절반은 여전히 맞다 — 375px 에서 막대 하나는 **6~7px** 이라 개별 막대를 읽을 수 없다. 하지만 이 차트가 하는 일은 막대 하나를 읽는 게 아니라 **분포의 모양**을 보여주는 것이고, 그건 6px 막대 45개로도 전달된다. 정확한 값은 차트 위 readout 이 준다.

- **모바일도 45개를 그린다.** 가로 스크롤은 만들지 않는다(폭에 맞춘다).
- **개별 막대를 컨트롤로 두지 않는다.** 6px 짜리는 터치 타겟 24×24(WCAG 2.5.8)를 만족할 수 없다. 대신 **차트 전체가 하나의 조작면**이고 포인터 x 좌표로 번호를 고른다. 호버·탭·좌우 방향키가 모두 같은 readout 을 갱신한다([[accessibility]] '작은 표적이 많은 그래프' 절).
- 전체 45개를 **넓게 펼친** 차트는 통계 상세 페이지가 `overflow-x: auto` 로 제공한다(막대당 24px↑). 거기서는 막대 하나하나가 `<button>` 이라 Tab 으로도 옮겨 다닐 수 있다.

이 규칙은 통계 카드 컴포넌트 사양([[components]])과 함께 적용한다.

## CLS 방지 (Core Web Vitals)

데이터가 늦게 도착해도 레이아웃이 밀리면 안 된다(초안 12.1). 비동기로 채워지는 슬롯은 도착 전에 자리를 예약한다.

- 번호 볼: 고정 크기 컨테이너.
- 차트: `aspect-ratio` 로 높이 예약.
- 뉴스 썸네일: `aspect-ratio` (예: `16 / 9`) + `object-fit: cover`.
- 광고 슬롯: `min-height` 예약. 광고가 비어도 자리를 지운다(→ [[components]] 광고 슬롯).
- 웹폰트: 시스템 폰트 폴백 스택을 남겨(→ [[design-tokens]]) 폰트 스왑 시 자리 이동을 최소화한다.

```css
.chart-slot { aspect-ratio: 16 / 9; }
.news-thumb { aspect-ratio: 16 / 9; object-fit: cover; }
.ad-slot    { min-height: 100px; }
```

## body 가로 스크롤 금지

페이지 `body` 는 절대 가로로 스크롤되지 않는다. 넓은 표·차트는 각자의 `overflow-x: auto` 컨테이너 안에서만 스크롤한다. 375px 폭에서 가로 스크롤이 생기면 세션 C 완료 기준(작업지시서 7.3)에 미달한다.

- 검증: 브라우저를 375px 로 좁혀 문서 전체에 가로 스크롤바가 없는지 확인.
- 넘칠 위험이 있는 요소: 긴 표, 45개 막대차트, 캐러셀. 이들은 자기 컨테이너 안에서 스크롤한다.

```css
.table-scroll { overflow-x: auto; }   /* 표는 여기서만 넘침 */
html, body { overflow-x: clip; }        /* 안전망 */
```

## prefers-reduced-motion

`@media (prefers-reduced-motion: reduce)` 를 존중한다. 캐러셀 자동 재생, 볼 등장 팝 애니메이션, 카드 호버 이동을 끈다.

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0ms !important;
    transition-duration: 0ms !important;
  }
}
```

캐러셀 자동 재생 로직은 CSS 뿐 아니라 JS 에서도 이 미디어쿼리를 `matchMedia('(prefers-reduced-motion: reduce)')` 로 감지해 타이머 자체를 걸지 않는다. 접근성 세부는 [[accessibility]].
