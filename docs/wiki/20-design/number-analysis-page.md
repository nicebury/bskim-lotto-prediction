# 번호 분석 화면

추천·꿈해몽 결과의 번호 한 벌을 받아 **역대 회차와 대조해 보여주는 화면**이다. 데이터는 전부 [[api-contract-analysis]] 한 번의 호출에서 온다.

---

## 왜 별도 화면인가

추천 결과 아래에 접어 두는 방법도 있었지만 세 가지가 걸린다.

1. **내용이 많다.** 네 블록에 표가 여럿이라 결과 카드 아래에 넣으면 카드가 아니라 문서가 된다.
2. **번호 한 벌마다 다르다.** 추천은 한 번에 여러 벌이 나온다. 전부 펼치면 화면이 감당하지 못한다.
3. **공유·북마크가 된다.** 주소에 번호가 들어 있어 "내가 뽑은 번호 분석" 을 그대로 보낼 수 있다.

---

## 주소

```
/lotto/analyze?numbers=3,11,24,29,38,41
```

번호를 **주소에 둔다.** 새로고침해도, 뒤로 갔다 다시 와도, 링크를 받아도 같은 화면이 나와야 하기 때문이다. 클라이언트 상태에만 두면 셋 다 깨진다.

⚠ **`searchParams` 를 읽으므로 이 페이지는 동적(`ƒ`)이다.** 그래도 서버 렌더링이라 JS 를 꺼도 본문이 나온다(완료 기준).

### ⚠ 색인하지 않는다

조합은 814만 가지다. 색인되면 **얇은 페이지가 무한히 생기는 것**과 같고, 애드센스 심사에서 "자동 생성 콘텐츠" 로 읽힌다.

- `robots: { index: false, follow: true }` — 내용은 따라가되 이 주소를 색인하지 않는다.
- `sitemap.ts` 에 넣지 않는다.
- 광고는 붙여도 된다(본문이 두껍다). `AdSlot` 자리 하나를 블록 2와 3 사이에 둔다.

---

## ★ 돌아왔을 때 번호가 그대로 있어야 한다

사용자가 명시적으로 요구한 것이다(2026-09-01).

> "뒤로가기 또는 돌아가기 누르면 다시 원래화면으로 → **중요: 뽑혀나왔던 번호 그대로 원래 페이지로 보여야 함**"

**문제.** 추천 결과는 클라이언트 상태(`useState`)에 있다. 분석 화면으로 이동했다가 돌아오면 그 상태가 사라져 **빈 화면에서 다시 뽑아야 한다.** 애써 나온 번호가 없어지는 것이라 사용자가 가장 싫어할 실패다.

**해결.** 결과를 `sessionStorage` 에 저장하고, 원래 화면이 마운트될 때 복원한다.

| 왜 이 방법인가 | |
|---|---|
| `router.back()` 만으로는 안 되나 | App Router 는 **클라이언트 상태를 복원하지 않는다.** 스크롤 위치만 돌려준다 |
| 주소에 결과를 담으면 | 여섯 벌이면 주소가 수백 자가 된다. 게다가 결과에는 `traits` 도 붙어 있다 |
| `localStorage` 는 | 탭을 닫아도 남는다. 며칠 뒤 들어왔는데 옛 추천이 뜨면 그게 더 이상하다 |
| **`sessionStorage`** | 탭이 살아 있는 동안만 유지된다. "잠깐 분석 보고 온다" 와 수명이 정확히 맞는다 |

⚠ **하드 내비게이션이어도 살아남는다.** 분석 링크는 [[adsense-readiness|`AdBreakLink`]] 라 광고를 켜면 문서를 새로 불러오는데, `sessionStorage` 는 그때도 유지된다. 이 설계를 고른 또 하나의 이유다.

### 저장 규약

```
lucky:reco:ai          AI 번호추천 결과
lucky:reco:six         6가지 추천 결과
lucky:dream            꿈해몽 결과
```

- **"분석" 을 누를 때가 아니라 결과를 받을 때 저장한다.** 누를 때 저장하면 뒤로가기·스와이프처럼 버튼을 거치지 않는 이동에서 비어 있다.
- 복원은 **첫 마운트 한 번만**. 사용자가 새로 뽑으면 덮어쓴다.
- 읽기·쓰기를 **전부 `try/catch`** 로 감싼다. 사파리 시크릿 모드는 `sessionStorage` 쓰기에서 예외를 던진다. 실패하면 복원을 포기할 뿐 화면은 정상이어야 한다.
- 저장한 JSON 의 모양이 다르면(배포로 타입이 바뀐 뒤) **조용히 버린다.** 낡은 데이터로 화면을 깨뜨리지 않는다.

### 돌아가기 버튼

화면 위아래 **양쪽**에 둔다. 네 블록을 다 읽고 나면 위로 올라가기 멀다.

- 동작은 `router.back()`. 브라우저 뒤로가기와 같아야 사용자가 혼동하지 않는다.
- ⚠ **직접 들어온 경우**(링크를 받았거나 새 탭) 뒤로 갈 곳이 없다. `window.history.length` 로 판단해 그때는 `/lotto/recommend` 로 보내는 링크를 대신 보인다.

## 화면 구성 — 네 블록

위에서 아래로 **내 번호 → 개별 → 조합 → 과거 대조**. 사용자가 정한 순서다.

### 머리

번호 여섯 개를 볼로 크게 보인다(공식 5구간 색). 그 아래 한 줄 요약과 `disclaimer`.

### 블록 0 — "1회차부터 매주 이 번호를 샀다면?"

```
총 구매   1,239회 × 1,000원 = 1,239,000원
당첨      4등 2회(100,000원) · 5등 31회(155,000원)
누적      255,000원
손익      -984,000원
```

- **`net` 을 가장 크게** 보인다. 이 블록은 "사면 번다" 가 아니라 **"1,239주를 사도 이렇게 된다"** 를 보여주는 자리다([[forbidden-expressions]]).
- ⚠ `unpriced` 가 비어 있지 않으면 **"금액을 확정할 수 없는 당첨이 있어 합계에서 제외했다"** 를 반드시 함께 쓴다. 1~3등 금액은 회차마다 다르고 소스에 없다.
- 손익은 색으로만 전달하지 않는다 — 부호를 글자로 쓴다(WCAG 1.4.1).

### 블록 1 — 번호별 지표

여섯 행짜리 표. 열은 `총 출현 / 최근 20 / 최근 50 / 마지막 출현 / 미출현`.

- ⚠ 모바일에서 열 다섯은 넘친다. **375px 에서는 번호마다 카드**로 접고, 768px 이상에서 표로 편다.
- 아래에 **45칸 격자**. 전체 출현 빈도를 색 농도로 깔고 내 번호에 테두리를 준다. 농도는 `frequency_grid` 의 최댓값 기준.
  - ⚠ **농도만으로 전달하지 않는다.** 각 칸의 `aria-label` 에 "12번, 168회 출현, 내 번호" 를 넣는다.
- `max_gap` 은 "과거 최대 32회차까지 안 나온 적이 있습니다" 로 쓴다. 미래형으로 쓰지 않는다.

### 블록 2 — 조합 패턴

`내 조합 / 역대 분포` 두 열로 나란히. 이 대조가 이 블록의 전부다 — 내 값만 보이면 흔한지 드문지 알 수 없다.

- **AC값·이월수·끝수합은 도움말이 필요하다.** 기존 `HelpTip` 을 쓴다. 정의는 [[api-contract-analysis]] 의 계산 정의 표를 그대로 옮긴다 — 커뮤니티마다 정의가 달라 우리 정의를 밝혀야 한다.
- 구간 분포는 가로 막대로. 기존 `.spec-minibar` 문법을 쓴다.
- ⚠ `reference` 의 값이 `null` 이면 그 행의 오른쪽 열만 비운다. 행 자체를 지우면 표가 회차마다 달라 보인다.

### 블록 3 — 과거 회차 대조

**가장 반응이 좋을 블록**이라 시각적으로 가장 강하게 만든다.

- 일치 개수 분포는 **3개 이상만** 표로 낸다(0~2개는 대부분이라 정보가 없다). 다만 합계가 `rounds_analyzed` 와 맞는지는 화면에 밝힌다.
- 근접 회차 TOP 5 는 **당첨번호 여섯 개를 볼로 그리고 겹친 번호를 강조**한다.
  - ⚠ 강조를 색으로만 하지 않는다. 겹친 볼에 테두리를 더하고 `aria-label` 에 "일치" 를 넣는다.
  - 회차 번호는 회차 상세로 가는 링크로 둔다.
- `exact_match_rounds` 가 비면 **"이 조합은 역대 한 번도 1등 번호로 나온 적이 없습니다"** 라고 쓴다. 거의 항상 그렇지만 그 자체가 정보다.

## 들어오는 길 — "분석" 버튼

지금 결과 카드의 액션은 `복사 / 이미지 저장 / 공유`(`BulkActions`)다. 여기에 **`분석`** 을 더한다.

- ⚠ **네 개 중 유일하게 색을 준다.** 나머지 셋은 결과를 밖으로 내보내는 도구이고, 분석만 **사이트 안으로 더 들어가는 문**이다. 성격이 다르므로 생김새도 달라야 한다.
- 위치는 **맨 앞**. 나머지 셋의 순서는 바꾸지 않는다(익숙한 자리를 옮기지 않는다).
- ⚠ 링크는 [[adsense-readiness|`AdBreakLink`]] 로 둔다. 사용자가 전면 광고를 원한 자리가 **정확히 여기**다("번호추천에 대한 분석을 눌러 페이지가 이동하게 되면"). 광고가 꺼져 있으면 평범한 `<Link>` 다.
- ⚠ 버튼이 아니라 **링크**여야 한다. 새 탭으로 열기·주소 복사가 되어야 하고, 스크린리더도 "이동" 으로 읽어야 한다.

## 접근성

- 네 블록은 각각 `<section aria-labelledby>`. 블록이 많아 랜드마크로 건너뛸 수 있어야 한다.
- 표는 `<caption>` 을 둔다. "무엇의 표인지" 가 표 안에 있어야 한다.
- ⚠ **색으로만 전달하는 곳이 세 군데**(45칸 농도·겹친 번호·손익 부호) 있다. 전부 글자나 테두리를 함께 준다.
- 숫자는 `formatNumber` 로 천 단위를 넣되 **회차 번호에는 넣지 않는다**(제1,239회가 되면 안 된다 — 2026-08-21 에 고친 적 있다).
