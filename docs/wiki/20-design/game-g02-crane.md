# G02 · 크레인 뽑기

**이 문서와 [[playground-game-contract]] 만 읽고 구현한다.**
소유 범위는 `frontend/src/games/g02-crane/` **뿐이다.**

> ★ **여섯 게임 중 가장 먼저 완주시킨다.** 구현이 가장 단순해서 호스트 계약의 구멍이
> 여기서 먼저 드러난다. 여섯이 동시에 같은 구멍에 빠지면 여섯 번 고쳐야 한다.
> 계약에 없는 것이 필요하면 **임의로 정하지 말고 멈춰서 보고한다.**

|------|-----|

| 유형 | **은닉형** — `awardHidden` (2026-09-08 개편) |

## 한 문장

좌우로 오가는 **전자석**을 탭으로 멈춰 원하는 **동물 볼** 위에 세우고, 한 번 더 탭해 내려 붙인다.
배출구에 넣으면 **볼이 깨지며 그때 번호가 나온다.** 가끔 꽝이 나온다(한 판 최대 2개).

## 2026-09-08 개편 — 무엇이 왜 바뀌었나

모바일에서 실제로 플레이해 본 사용자의 피드백이 출발점이다. 바뀐 것이 많아 **이 절이 이전
사양보다 우선한다.**

| 바뀐 것 | 왜 |
|---------|-----|
| stage 600 → **430** | 모바일에서 소개글 + 상단 여백 + 세로 600 캔버스가 겹쳐 **스크롤하지 않으면 플레이할 수 없었다.** 470 으로 한 번 줄인 뒤 실제로 찍어 보니 조작 버튼이 하단 탭바에 물려 430 까지 내렸다 |
| 예약형 → **은닉형** | 번호를 감추고 동물 볼로 바꿨다. 번호가 보이지 않으면 예약할 이유가 없다 — 계약의 *"보이지 않았다면 중복을 아예 만들지 않는다"* 가 그대로 적용된다 |
| 캡슐 14개 2줄 → **볼 6개 1줄** | 두 줄이면 위 줄이 아래 줄을 가려 **왼쪽 아래 볼이 아예 선택되지 않았다.** 한 줄이면 모든 볼이 언제나 집을 수 있다 |
| 허용 오차 `[26…13]` → **볼 지름의 고정 비율** | 오차가 획득 수에 따라 조용히 줄어드는 것보다, **언제나 같은 규칙**이 정직하다. 20% → 30%(09-10) → 20%(09-16) → **25%**(09-17) 로 오갔다. 비율만 보고 판단하다 실제 픽셀이 좁아진 사고가 있었다 → "2026-09-17" 절 |
| 무제한 시도 → **9번** | 끝이 없으면 긴장이 없다. 9번에 6개는 세 번까지 빗나가도 되는 여유다 |
| 조준 링 | **뺀다.** 볼에 동그라미를 치면 "이건 확정" 처럼 보여 오히려 판정을 가린다 |
| 조준선 | **그리지 않는다**(2026-09-16 사용자 결정). 왕복 중에 뺐다가(09-10) 멈춘 뒤의 실선까지 마저 뺐다 — 한 줄로 늘어선 볼 위에서는 **자석 자체가 이미 조준선**이라 선을 하나 더 그으면 화면만 복잡해진다 |
| 캔버스 안 조작 버튼 | 빨간 누름 버튼을 게임기 하단에 그린다. 라벨이 `멈춤` ↔ `내림` 으로 바뀌어 **다음에 할 일이 버튼에 적혀 있다** |

## 화면 구성 (360 × 430)

기계 외장(둥근 사각 `x6 y4 w348 h422 r20`, `--color-primary` 그라디언트, 헤더 이름판 +
도트 램프 5개) + 유리창(`x 20~340, y 40~308`) + 레일(y=62) + 자석 + **볼 6개 한 줄**(y=262) +
우측 배출구(`x 302~340`, 깨지는 높이 y=276) + **하단 조작 패널**(y 314~, 빨간 누름 버튼 하나).

⚠ **좌표의 정본은 `layout.ts` 다.** 이 줄들은 읽는 사람이 화면을 머릿속에 그리기 위한 것이고,
값이 어긋나면 코드가 맞다. 2026-09-16 에 물체를 키우면서 이 절이 한 번 낡았다.

⚠ 게임기 상단 여백을 최소로 한다. 램프와 유리창 사이에 장식을 넣지 않는다 — 세로가 짧아진
만큼 **모든 여백이 곧 게임 공간의 손실**이다.

⚠ **남은 기회는 유리창 안 "레일 위" 띠에 그린다**(y=51 = `GLASS_T + 11`). 조작 패널에 두면 빨간 버튼 라벨과
정면으로 겹치고(첫 캡처에서 "남은 기회 9" 가 "멈춤" 위에 얹혔다), 레일 아래는 자석이
왕복하는 길이라 무엇을 두든 언젠가 가린다. **레일 위가 영영 비어 있는 유일한 띠다.**

## 번호 획득 — 은닉형

**볼에는 번호가 없다.** 동물 아이콘만 있다. 배출구 낙하가 끝나는 순간 볼이 **깨지고**,
그때 `pool.awardHidden()` 이 번호를 정한다. 꽝이면 `pool` 을 아예 부르지 않는다.

번호가 미리 보이지 않으므로 남은 풀에서 뽑아도 모순이 없다 — **중복이 구조적으로
불가능하다**(계약 "세 유형" 표의 은닉형과 같은 근거).

동물은 6종이고 색은 `palette.svc` 여섯 개를 그대로 쓴다. 번호가 붙지 않은 볼이므로 공식
5구간 색을 쓰지 않는다(계약: *번호가 붙은* 볼·캡슐·링·칸만 5구간).
**깨진 뒤 나오는 번호 볼은 `draw.ball()` 로 그린다** — 거기서부터는 공식 색이다.

집힌 자리에는 새 볼이 위에서 떨어져 채운다. 항상 6개를 유지한다.

## 물리와 수치 (물리 엔진 없음, 좌표 이동만)

- 자석 x 왕복 `[46, 282]`, 속도 **85 px/s**(핑퐁). `primary` → 즉시 정지. 편도 2.78초.
  ⚠ **속도는 난이도가 아니라 조작 가능성을 정한다.** 창이 10.5px 이므로 창 안에 머무는
  시간이 `21 ÷ 85 = 0.247초` — 누르는 타이밍이 **±0.124초**까지 어긋나도 집힌다.
  95 일 때는 ±0.088초였고 그것이 "너무 어렵다" 의 실체였다(2026-09-17).
  ⚠ 더 내리지 않는다. 편도가 길어지면 **겨눌 볼이 올 때까지 기다리는 시간**이 늘어
  어려움 대신 지루함이 온다.
- 두 번째 `primary` → 하강 260 px/s. 볼 표면(`y = ball.y − GRAB_OFFSET`, 34px 위)에서 정지.
  집을 볼이 아예 없으면 `y=240`(볼 표면보다 **더 아래**)까지 내려간다 — 헛집음이 눈에
  보여야 "빗나갔구나" 가 납득된다.
- **집기 판정** — 자석 x 와 볼 중심의 거리로 세 갈래. (볼 반지름 **21**, 지름 42)
  | 거리 | 결과 |
  |------|------|
  | `≤ 10.5px` (볼 지름의 **25%** = `GRAB_WINDOW`) | **집는다** |
  | `≤ 21px` (볼 반지름 = `GRAB_TOUCH`) | 붙었다가 **올라가다 떨어뜨린다** |
  | 그 밖 | 빈손 |
- **놓치는 높이는 빗나간 정도에 비례한다.** 창 바로 밖이면 `y≈112`(거의 다 올라간 뒤)에서,
  가장자리를 겨우 걸쳤으면 `y≈206`(조금 올라가다)에서 자력이 끊긴다.
  같은 실패라도 "거의 될 뻔했다" 와 "많이 빗나갔다" 가 다르게 보여야 다음 시도를 어떻게
  고칠지 알 수 있다. **실패를 벌이 아니라 피드백으로 만드는 장치다.**
- 상승 300 px/s → 배출구까지 220 px/s 수평 → 낙하 400 px/s.
- 볼 줄은 y=262 고정 + `rng.range(-2, 2)` 지터. 슬롯 6칸을 `[47, 281]` 에 균등 배치
  (간격 **46.8px**, 지름 42보다 넓다).
- **더미 재정렬** — 1차원 완화. 최소 간격 **43px** 위반 시 서로 `±(43−d)/2`,
  목표 x 로 `approach(cur, target, 90*dt)`. 떨어지는 볼이 있으면 반복을 늘린다.
  ⚠ **최소 간격과 슬롯 간격 사이에 여유가 있어야 완화가 수렴한다.** 볼을 18 → 21 로
  키웠을 때 여유가 1.6px 로 줄어 리필 볼이 밀어낸 뒤 목표 간격으로 돌아오지 못했다
  (실측 43.3~43.7). 최소 간격을 낮추고 배치 폭을 함께 넓혀 3px 대로 되돌렸다.

### 이미 끝난 판으로 시작될 때

호스트가 완주 기록을 복원하면 `pool` 이 이미 가득 찬 채로 `create` 된다. 첫 `fixedUpdate`
에서 `pool.complete` 를 확인해 **`ready` 대신 `cleared` 를 보내고 내부 상태도 멈춘다.**
→ [[playground-game-contract]] "이미 끝난 판으로 시작될 때" (여섯 게임 공통)

### ★ 가짜 실패를 넣지 않는다 (그대로 유지한다)

**판정은 전부 거리로 결정된다. 확률이 한 줄도 없다.** 떨어뜨리는 것조차 "창 밖이었다" 는
결정론적 결과다. 실제 인형뽑기의 집게 힘 조작은 사행성 규제 대상이고, 사용자가 "조작당했다"
고 느끼는 첫 번째 이유다 ([[0014-number-playground]] "지켜야 할 것").

그 정직함이 화면에서 읽히려면 **어디를 겨누는지 보여야** 한다. 처음에는 조준선을 그렸지만
2026-09-16 에 전부 걷어 냈다 — 볼이 **한 줄로 늘어서 있고** 자석이 바로 그 위를 지나므로,
**자석의 가로 위치가 곧 조준선**이다. 선을 하나 더 그으면 정보가 늘지 않고 화면만 복잡해진다.
(두 줄이던 시절에는 어느 줄을 겨누는지 모호해 선이 필요했다. 한 줄로 바꾸며 그 이유가 사라졌다.)

## 기회 — 9번

자석을 내릴 때마다 1회 소모한다. `emit({type:'attempt', used, total: 9})`.
남은 기회는 유리창 안 "레일 위" 띠에 그린다(캔버스를 보는 사람 기준). 9번을 다 쓰고도
6개를 못 채우면 `phase: 'failed'`.

⚠ **말로도 알린다** — 내리는 순간 `emit({type:'status', text:'남은 기회 N번'})`.
캔버스에 그린 숫자는 보조기술에 완전히 투명하고, 호스트 HUD 는 아직 `attempt` 를 쓰지 않아
(`GameCanvas` 가 조용히 버린다) 이 한 줄이 유일한 통로다(계약: *남은 기회는 캔버스 안에도
그린다*). 보내는 자리를 **내리는 순간**으로 잡아야 획득 `status`(볼이 깨질 때 호스트가
보낸다, 1초 이상 뒤)와 같은 `aria-live` 영역을 서로 덮어쓰지 않는다.

빗나가도 기회는 소모된다 — 그래야 9번이라는 숫자에 의미가 생긴다.

## 진행 단계 — 호스트가 버튼을 그린다

캔버스에 그린 버튼은 보조기술에 보이지 않고 페이지 스크롤도 할 수 없다. 그래서 **게임은
단계만 알리고 버튼은 호스트가 캔버스 위 DOM 오버레이로 그린다**(계약의 `phase` 이벤트).

★ **문구는 호스트가 기본값을 갖는다**(계약 2026-09-16). 게임이 채우는 것은
*게임마다 달라야 하는 것* 뿐이다. 2026-09-10 의 "게임이 고정 문구를 보낸다" 는 폐기됐다 —
같은 문장을 여섯 곳에 복사해 두면 하나를 고칠 때 나머지 다섯이 남는다.

| 단계 | 게임이 보내는 문구 | 호스트가 그리는 버튼 |
|------|------------------|--------------------|
| `ready` | **없음** — 호스트가 제목 + `tagline` 으로 채운다 | **게임시작** |
| `playing` | — | 없음 |
| `failed` | `text` 만 — `번호 N개를 모았습니다. 다시 도전해 보세요.` | **다시하기 · 다른 게임하기** |
| `cleared` | **없음** — 완료 화면에는 이 게임만의 것이 없다 | **다시하기 · 번호확인** |

실패에서 `text` 만 덮는 이유는 **몇 개를 모았는지**가 이 게임에서만 나오는 값이고, 9번을 다
쓴 사람에게 화면에 남는 유일한 성과이기 때문이다. 제목은 호스트 기본값(`6개 번호 모으기 실패`)
을 쓴다.

⚠ `ready` 는 **`create` 직후 첫 `fixedUpdate` 에서** 보낸다. 그 전에는 화면이 그려져 있어야
하므로 게임은 `ready` 에서도 배경·기계·볼을 전부 그린다 — 빈 캔버스에 버튼만 뜨면 무엇을
시작하는지 알 수 없다.

## 조작 버튼 — 캔버스 안 빨간 누름 버튼

게임기 하단 패널 중앙에 지름 **72px** 원형 버튼을 그린다(2026-09-16 에 68 → 72).
라벨이 상태를 말한다.

| 상태 | 라벨 |
|------|------|
| 왕복 중 | `멈춤` |
| 정지 후 | `내림` |
| 그 밖(하강·상승·운반) | 흐리게, 라벨 `…` |

⚠ 이 버튼은 **장식이 아니라 진짜 어포던스**다. 캔버스 어디를 눌러도 `primary` 가 들어오지만
(계약: 입력 절), 무엇을 눌러야 하는지 보이는 것과 보이지 않는 것은 완전히 다른 게임이다.
⚠ 버튼을 누르는 애니메이션(눌림 2px + 그림자 축소)을 넣는다. 반응이 없으면 눌렸는지 모른다.

## 아트 디렉션 (코드로 그린다)

**동물 볼** — 원(`r21`) + `palette.svc` 색 + 흰 배 + 귀·눈·코. 6종(고양이·강아지·토끼·곰·
여우·병아리)을 **코드로만** 그린다. 이미지 파일을 쓰지 않는다.

**깨짐** — 배출구 바닥에 닿는 순간 껍질 조각 6개가 튀고, 그 자리에서 `draw.ball()` 로 번호가
떠오른다. `reducedMotion` 이면 조각 없이 페이드로 바꾼다.

**자석** — 세로 로드 + 몸체 `44 × 26`. 볼은 **아래 면**에 붙는다(`GRAB_OFFSET` = 34).
접촉면이 accent 로 물들고 자기장 아크 두 개가 퍼진다 — 자력이 흐르는지가 한눈에 보인다.
(집게였을 때의 발톱 사양은 2026-09-16 에 폐기됐다 → 아래 "자석" 절)

**기계** — 외장에 도트 램프 5개(순차 점멸). 배경은 오락실 카펫 패턴(마름모 격자 α0.06).

## 2026-09-16 개편 — 자석 · 꽝 · 크기

실제로 플레이한 사용자의 지적 다섯 가지를 반영했다.

| 지적 | 고친 것 |
|------|--------|
| "게임 사이즈가 조금 작음" | **캔버스 안의 물체를 키웠다** — 볼 18 → **21**, 자석·버튼·유리창 확대. stage 비율은 그대로다(아래 ⚠) |
| "30%면 조금 크다, 20%로" | 집기 창 `BALL_R*2*0.3` → **`*0.2`**(±8.4px). ⚠ **2026-09-17 에 25% 로 되돌렸다** — 아래 절 |
| "꽝이 필요. 9회에 2번 이하" | **봉투 방식**으로 꽝 최대 2장([[0014-number-playground]] 예외 확대). 연출은 번호 공개보다 크고 길게 |
| "집게가 공 앞에 겹쳐 잡히는 느낌이 없다. 자석이 낫겠다" | 집게를 **전자석**으로 교체 |
| "디자인이 투박하다. 게임박스 자체가" | 헤더 이름판·베젤·좌우 기둥·리벳·스피커 그릴 추가 |

⚠ **stage 비율(360:430)을 세로로 늘리지 않는다.** 호스트는 무대 높이를 먼저 정하고
`aspect-ratio` 로 폭을 줄인다 — **세로로 길수록 모바일에서 폭이 좁아진다.** 390×760 기준
높이 예산이 약 468px 라 지금 비율은 폭 390 을 꽉 채우는 경계에 딱 걸쳐 있다. 430 을 460 으로
늘리면 폭이 374 로 **오히려 작아진다.** 크게 보이게 하려면 비율이 아니라 **물체**를 키운다.

### 자석 — 집게를 대체한 이유

집게는 발톱이 볼 **앞을 덮어** 가리기만 하고 맞물리는 느낌이 없었다. 벌림각을 조정해도
겹침 자체는 사라지지 않는다 — 앞에서 감싸는 기구이기 때문이다.

자석은 **위에서 붙는다.** 볼이 통째로 보이고, 접점이 한 점이라 어긋남이 눈에 띄지 않는다.
*"잡는 기구를 정교하게 그린다"* 가 아니라 **"가리지 않는 기구로 바꾼다"** 가 답이었다.

- 몸체 `44 × 26`. 볼은 아래 면에 붙는다(`GRAB_OFFSET = MAG_H/2 + BALL_R`).
- 접촉면이 accent 로 물들고, 붙는 동안 자기장 아크 두 개가 퍼진다. **자력이 흐르는지가
  한눈에 보인다.**
- 놓칠 때는 자력이 끊겨 볼이 스르륵 떨어진다 — 빗나간 정도에 따라 떠나는 높이가 다르다.

### 꽝 — 봉투에서 뽑는다

`BLANK_POOL`(12)장 봉투에 꽝 `BLANK_COUNT`(2)장을 섞고, **볼을 만들 때** 한 장씩 꺼낸다.
집는 순간에 굴리지 않는다.

- 한 판의 꽝은 **최대 2개**. 확률이면 운 나쁜 판에서 다섯 번 터질 수 있고, 그것이 정확히
  ADR 이 막으려던 "조작당했다" 는 정서다.
- 꽝 볼은 겉모습이 **보통 볼과 완전히 같다.** 구분되면 집기 전에 알게 되어 재미가 사라진다.
- 꽝이면 `pool` 을 아예 건드리지 않는다 — 번호가 소모되지 않고, 그 시도만 사라진다.
- 연출은 `BLANK_TIME`(1.4초)로 번호 공개(1.0초)보다 **길다.** 터진 자국(톱니 원) + 큰 글자 +
  `blank` 효과음 + 화면 흔들림. **파티클보다 맨 마지막에 그린다**(G01 교훈).

## 2026-09-17 개편 — 집기가 너무 어려웠다

사용자 지적: *"공을 들어올리기가 너무 어려워."*

### 원인 — 비율만 보고 두 변경을 겹쳤다

09-16 에 **볼을 18 → 21 로 키우면서 동시에 창을 30% → 20% 로** 내렸다. 둘 다 "화면이 나아진다"
는 판단이었지만 **집기 난이도에는 같은 방향으로 작용**했고, 그 결과 사용자가 *"조금 크다"* 고
했던 09-10 의 10.8px 보다 **오히려 22% 좁은** 8.4px 이 됐다.

| 시점 | 볼 지름 | 비율 | 허용 오차 | 속도 | **타이밍 여유** |
|------|--------|------|----------|------|----------------|
| 09-10 | 36 | 30% | 10.8px | 95 | ±0.114초 |
| 09-16 | 42 | 20% | 8.4px | 95 | **±0.088초** |
| **09-17** | 42 | **25%** | **10.5px** | **85** | **±0.124초** |

★ **비율이 아니라 픽셀과 시간으로 잰다.** "20%" 는 볼 크기가 바뀌면 다른 게임이 된다.
사용자가 실제로 겪는 것은 비율이 아니라 **누르는 타이밍이 얼마나 어긋나도 되는가**다.

### 고친 것 — 창과 속도를 나눠 손댄다

사양서가 원래 정한 원칙 그대로다 — **난이도는 창이 만들고 조작 가능성은 속도가 만든다.**
그래서 "어렵다" 에 창만 넓히지 않았다.

- **창 20% → 25%**(±10.5px). 정확도 요구를 09-10 수준(10.8px)으로 되돌린다. 더 넓히면
  사용자가 그때 *"조금 크다"* 고 한 자리로 다시 간다.
- **속도 95 → 85**. 창 통과 시간이 0.177 → **0.247초**. 여유의 대부분이 여기서 나온다.
  ⚠ 왕복 편도가 2.48 → 2.78초로 길어진다. 더 내리면 기다리는 시간이 지루해진다.

### 실측 (헤드리스 7판)

| 항목 | 결과 |
|------|------|
| 조준했을 때 빈손 | **0** — 창 안이면 여전히 100% 집힌다(확률 0 유지) |
| 무작위로 눌러 9번 소진 | 4개 → **5개** 획득. 같은 시드에서 한 개 늘었다 |
| 한 판 길이 | 18.6 ~ 23.7초 (`paceSeconds` 35 안) |
| 번호 중복 | 0 |

## 효과음 (2026-09-10 적용)

계약의 여섯 어휘를 **전부** 쓴다(2026-09-16 에 꽝이 생기며 `blank` 이 합류했다).

| 이름 | 크레인에서 언제 |
|------|----------------|
| `shoot` | **자석을 내릴 때.** 멈추는 것은 조준일 뿐이라 소리를 내지 않는다 |
| `hit` | 볼이 깨져 번호가 나왔을 때. **단, 여섯 번째는 보내지 않는다** |
| `miss` | 빈손으로 올라올 때 · 올라가다 놓칠 때 |
| `blank` | **꽝이 나왔을 때**(2026-09-16) |
| `clear` | 6개를 다 모았을 때 |
| `fail` | 9번을 다 썼을 때 |

⚠ 발사음은 **결과를 기다리지 않고 먼저** 울린다. 집히는지 확인한 뒤 소리를 내면 손끝과
귀가 어긋나 조작이 굼떠 보인다(계약: 효과음 규칙).
⚠ 마지막 한 개에 `hit` 과 `clear` 를 겹쳐 보내지 않는다. 팡파르가 뭉개지고, 어차피
팡파르가 그 한 개를 말해 준다.

## 캔버스가 지키는 나머지 계약

| 항목 | 이 게임에서 |
|------|------------|
| 오프스크린 배경 캐시 배율 | `getTransform().a` 를 읽는다. **고정 배율을 쓰지 않는다** — 고배율 화면에서 배경만 뭉갠다. 배율이 달라지거나 1.5초가 지나면 다시 굽는다(테마 전환 흡수) |
| `--color-warning` | **쓰지 않는다.** 연한 배경 위 경고 *글자용* 토큰이라 라이트 모드에서 어두운 갈색이다. 램프·남은 기회 점·병아리 부리의 밝은 주황은 `svc.reco` 다 → [[log]] 2026-09-10 함정 |
| 획득 `status` | **게임이 보내지 않는다.** 호스트가 `pool` 콜백에서 "N번째 번호 17번을 모았습니다" 를 이미 보내고, 게임이 덧쓰면 같은 `aria-live` 영역을 덮어 정보가 오히려 준다 |
| 실패 `status` | **게임이 보낸다.** *기회를 다 썼다* 는 호스트가 알 수 없고, 오버레이는 `aria-live` 가 아니라 자동으로 읽히지 않는다 |
| 꽝 `status` | **게임이 보낸다.** 화면을 보지 않는 사용자에게 "왜 번호가 안 늘었는지" 를 알릴 유일한 통로다 |
| 팝업 문구 | `ready`·`cleared` 는 **보내지 않는다**(호스트 `defaultCopy`). `failed` 만 **`text` 를** 모은 개수로 덮는다 → 위 "진행 단계" 표 |

## 검증 결과 (2026-09-08 개편판)

⚠ **이 절은 09-08 시점의 기록이다.** 그 뒤 09-16 에 볼·자석 크기와 집기 창(30% → 20%)이
바뀌었으므로 표의 수치를 현재 사양으로 읽지 않는다. 결론(확률 0 · 중복 0 · 9번이면 반드시 끝)
은 그대로 유효하다.

호스트 없이 게임 모듈만 헤드리스로 돌려 12개 시나리오를 검산했다. 가짜 캔버스 컨텍스트가
그리기 호출을 엿들어 자석 위치·볼 좌표를 밖에서 읽는다.

| 항목 | 결과 |
|------|------|
| **창(당시 ±30%) 안에서 눌렀는데 빈손** | **0** — 창 안이면 100% 집힌다 |
| 정확히 조준하면 | **6번 시도로 6개** (기회 9번 중 3번 남김) |
| 대충 누르면 | 9번을 다 쓰고 **반드시 `failed`** — 무한히 계속되지 않는다 |
| 번호 중복 | 0 (은닉형이라 구조적으로 불가) |
| 최소 간격(38px) 위반 | 0 |
| 재시작(`destroy` → `create`) 3회 | 예외 없음 |
| 움직임 최소화 · 저사양 | 완주 |
| 완주 기록 복원 | 첫 스텝에 `cleared`. "시작" 을 눌러도 판이 다시 굴러가지 않는다 |
| 효과음 규약 | `shoot` 이 시도 수와 일치 · `hit` 은 완주분 제외 · `clear`/`fail` 은 끝에 한 번 |

### ⚠ 여기서 잡은 버그 하나

착지 뒤 **튀어 오르는 볼**이 `falling` 로 남아 집기 대상에서 빠졌다. 화면에는 멀쩡히 보이는
볼을 겨눠 창 안을 맞췄는데 빈손이 나온다 — **사용자에게는 조작으로 읽히는 바로 그 상황이다.**
아홉 번 중 한 번꼴로 재현됐다. `falling` 을 "아직 제자리에 닿지 않음" 으로 좁히고, 닿는
순간 집을 수 있게 고쳤다. 남은 튐은 연출일 뿐이다.

## 검증 결과 (2026-09-16 · 문구 위임 이후)

두 층으로 나눠 봤다. **이벤트가 맞는지는 헤드리스 모듈로, 화면에 실제로 그렇게 뜨는지는
CDP 로** 본다 — 게임이 옳게 보내도 호스트가 다르게 그리면 사용자에게는 그것이 사실이다.

### 헤드리스 모듈 7판 (호스트 없이 `fixedUpdate`·`draw`·`handle` 만)

| 항목 | 결과 |
|------|------|
| `cleared` 에 실린 문구 | **0건** — 다섯 판 전부 호스트에 위임 |
| `failed` 에 실린 문구 | `text` 만, 모은 개수 포함 |
| 남은 기회 `status` | 시도 수와 일치 |
| **조준했을 때 빈손** | **0** — 창(당시 ±8.4px) 안이면 100% 집힌다. 09-17 에 ±10.5px 로 넓힌 뒤에도 같다 |
| 번호 중복 | 0 |
| 꽝 | 판당 최대 2 (봉투대로) |
| 마지막 획득 | `hit` 없이 `clear` 만 |
| 대충 눌렀을 때 | 9번을 다 쓰고 반드시 `failed` |

### CDP 실측 (완주까지 진행시켜 DOM 을 읽음)

시작 오버레이 `크레인 뽑기` + `tagline`, 완료 오버레이 **`6개 공을 모두 모았습니다` /
`아래에서 모은 번호를 확인할 수 있어요.`** — 전부 **호스트 기본 문구**다. 버튼은
`다시하기`·`번호확인`. `aria-live` 에 `남은 기회 8번…` 이 실제로 나왔고, 획득 안내
(`15번을 모아 번호 6개가 완성되었습니다.`)는 호스트가 보냈다.

⚠ **`--virtual-time-budget` 스크린샷에는 시작 오버레이가 찍히지 않는다.** 가상시간에서
첫 `fixedUpdate` 가 돌기 전에 찍히기 때문이고, 오버레이는 처음부터 떠 있었다.
**상태 전환은 스크린샷이 아니라 DOM 조회로 판정한다.**

## 완료 기준

[[playground-game-contract]] 의 공통 완료 기준에 더해:
- 판정에 확률 요소 0. 창(볼 지름의 **25%** = ±10.5px) 안이면 100% 집힌다.
  ⚠ **꽝은 여기서 예외가 아니다** — 꽝은 *집기* 가 아니라 *보상* 의 문제이고, 봉투에서
  볼을 만들 때 이미 정해져 있다([[0014-number-playground]] 예외 확대, 2026-09-16).
- 볼 6개가 완화 후 서로 겹치지 않는다(최소 간격 **43px**).
- 키보드(스페이스 두 번)만으로 완주 가능.
- 9번을 다 쓰면 반드시 `failed` 로 끝난다 — 무한히 계속되지 않는다.
- **375px 폭 모바일에서 스크롤 없이 게임기 전체와 조작 버튼이 보인다.**
