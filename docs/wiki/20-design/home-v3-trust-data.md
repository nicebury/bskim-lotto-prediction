# 새 메인 `front_v2` — 디자인 언어 "트러스트 데이터"

> ## ✕ 미채택 · 코드 삭제됨 (2026-09-02)
>
> 사용자가 `front_v2/` 를 지웠다. **이 코드는 git 에 없다** — 한 번도 커밋되지 않은 채로
> 삭제됐으므로 [[home-v2-concept]] 과 달리 **커밋에서 꺼낼 수 없다.** 다시 필요하면 이
> 문서를 보고 새로 만들어야 한다.
>
> **이 페이지는 지우지 않는다.** 시안은 버렸지만 아래 두 가지는 다음에 무엇을 만들든 값을
> 한다 — ① 40~60대·모바일이라는 사용자 조건에서 내린 결정들(본문 17px, 헤어라인 조판,
> 강조색 잠금)과 ② "실측하며 밟은 함정" 절의 세 가지. 아래 본문은 당시 기록이라 현재형으로
> 쓰여 있다.

기존 홈(`frontend/src/app/(site)/page.tsx`)을 **교체하지 않는다.** 두 안을 나란히 띄워 놓고
하나를 고르기 위한 비교용 메인이다. 폐기된 [[home-v2-concept]] 과 달리 이번에는
**앱 자체를 복제**했다 — 같은 앱 안에 두 디자인 언어를 욱여넣으면서 생기는 CSS 격리 비용이
그 시안을 갉아먹었기 때문이다.

## 무엇이 다른가

| | 기존 홈 | front_v2 |
|---|---|---|
| 위치 | `frontend/` (포트 3000) | `front_v2/` (포트 3100) |
| 본문 글자 | 15.2px | **17px** |
| 구획 | 카드 테두리 + 그림자 | 헤어라인 + 여백 |
| 히어로 | 일러스트(`HeroArt`) + 카피 | **잉크 네이비 패널에 최신 회차 데이터** |
| 강조색 | `--color-primary` + 서비스 6색 | 코발트 하나로 잠금. 채도는 볼 5색에 집중 |
| 통계 | 탭 4종(StatBoard) | 빈도 순위 + **45칸 분포 격자** |
| 가이드 | 가로 캐러셀 | 4열 벤토(2×2 + 4) |
| 모션 | 없음에 가까움 | CSS scroll-driven, JS 0 |

**섹션은 하나도 늘리거나 줄이지 않았다.** 순서와 시각적 비중만 다시 잡았다. SEO 자산(서비스
소개 본문·FAQ 구조화 데이터)과 애드센스 심사용 본문이 그대로 남아야 하기 때문이다.

## 결정의 근거

### 주 사용자는 40~60대, 기기는 모바일

- **본문 17px.** 체감 차이가 가장 큰 한 가지다. 되돌리기 전에 실제 기기에서 읽어 볼 것.
- **터치 타겟 52px.** 최소치 44px 보다 여유를 뒀다([[responsive-rules]]).
- 정보 밀도는 낮추지 않았다. 한국 40~60대 사용자에게 여백만 많은 화면은 "빈약한 사이트" 로
  읽힌다. 밀도를 유지하되 **줄 간격과 구획**으로 읽히게 만드는 쪽을 택했다.

### "화려함" 이 아니라 "전문성" 이 요구였다

사용자의 요구는 *"화려하고 이쁜 것도 중요하지만 전문 사이트의 느낌"* 이었다. 그래서
에이전시·포트폴리오 계열의 장치(대형 세리프, 스크롤 하이재킹, 커서 효과, 마키)를 전부 뺐다.
대신 증권·은행 앱의 어법을 가져왔다.

- 히어로에 일러스트 대신 **최신 회차 당첨번호**를 앉혔다. 사람들이 이 사이트에서 가장 먼저
  확인하려는 사실이 화면에서 가장 무거운 자리를 차지해야 한다.
- 카드 테두리를 걷어냈다. 테두리가 많을수록 "정보 모음" 으로 읽히고, 헤어라인 조판일수록
  "서비스" 로 읽힌다.
- 숫자는 전부 `tabular-nums`. 회차·횟수·카운트다운이 자리에서 흔들리지 않는다.

### 팔레트 — 강조색은 하나

`--v2-accent` 코발트(`#1b4dd8` / 다크 `#8aa4ff`) **하나만** 쓴다. 링크·CTA·포커스 링·빈도
막대·히트맵이 전부 이 색의 농도 차이다. 채도의 주인공은 이미 있다 — **동행복권 공식 볼 5색**
([[0009-official-ball-colors-over-mockup]]). 서비스 6색(`--svc-*`)은 사이트 전역의 카테고리
색 언어라 그대로 읽어 쓰되, 진한 타일이 아니라 **연한 배경 + 진한 글리프**로 낮췄다.

잉크 패널(`--v2-ink` `#101b33`)은 **라이트·다크 양쪽에서 똑같이 어둡다.** 테마를 따라 뒤집으면
라이트 모드에서 히어로가 흰 판이 되어 앵커 역할을 잃는다. 페이지에서 명암이 뒤집히는 곳은
이 한 군데뿐이다.

## 45칸 분포 격자

로또의 정의가 "45개 중 여섯 개" 다. 그래서 장식 그래픽을 새로 그리는 대신 그 격자 자체를
시각 요소로 삼았다. 10열 × 5행이고 **각 행이 곧 볼 공식 5구간**이라 구조가 정보를 담는다.

두 정보를 **다른 채널**로 겹쳐 놓았다.

| 정보 | 채널 |
|---|---|
| 최근 20회 출현 빈도 | 배경 명암 5단계 |
| 최신 회차 당첨번호 | **모양** (사각 칸들 사이의 동그란 볼, 공식 색) |

같은 채널을 쓰면 둘 중 하나를 읽을 수 없다.

- **셀에 링크·버튼을 달지 않는다.** 375px 폭에서 셀이 약 30px 라 터치 타겟 44px 을 지킬 수
  없다([[responsive-rules]]). 번호별 이동은 격자 밖 44px 링크로 낸다.
- **명암은 연속이 아니라 5단계다.** `color-mix()` 로 농도를 연속 계산하면 그 위 숫자가 어느
  지점에서 AA 아래로 떨어지는지 보장할 수 없다. 단계를 끊고 배경-글자 짝을 손으로 검증했다.
- **격자 자체는 `aria-hidden`** 이다. 45칸을 하나씩 읽히면 소음이 된다. 대신 바로 아래 문장이
  최다·미출현을 말로 요약한다 — 색이 정보의 유일한 전달자가 되지 않게 하는 장치이기도 하다
  ([[accessibility]]).

## 모션 — JS 를 한 줄도 쓰지 않는다

`MOTION` 은 낮게 잡았다(10점 만점에 4). 저가 안드로이드에서 스크롤이 끊기면 안 되고,
정보 사이트에서 모션은 리듬 이상을 해선 안 된다.

- 스크롤 리빌은 **CSS scroll-driven animation**(`animation-timeline: view()`)이다.
  IntersectionObserver 로 클래스를 붙이는 방식은 **JS 가 없으면 콘텐츠가 숨은 채로 남는다** —
  "JS 를 꺼도 본문이 보인다" 는 완료 기준을 잃는다. `@supports` 밖 브라우저에서는 아무 일도
  일어나지 않고 콘텐츠가 처음부터 보인다.
- 전체를 `@media (prefers-reduced-motion: no-preference)` 안에 넣었다. 모션을 끈 사용자에게는
  애니메이션이 **선언조차 되지 않는다.**
- `window.addEventListener('scroll')` 을 쓰지 않는다.

## 격리 규칙

`front_v2/src/styles/home-v2.css` 한 파일이고, 전부 `.v2home` 스코프 안에 있다.
다른 페이지는 기존 스킨 그대로 살아 있다.

1. 모든 클래스는 `v2-` 접두, 모든 커스텀 프로퍼티는 `--v2-` 접두.
2. `:root` 토큰([[design-tokens]])을 **한 줄도 덮어쓰지 않는다.** 읽기만 한다.
3. 무조건 선택자(`h2`, `a`, `ul`)를 쓰지 않는다. 항상 `.v2home` 아래에서 건다.
4. `!important` 를 쓰지 않는다. 특이도로 이긴다.
5. `globals.css` 에서 **맨 마지막에** import 한다. 같은 특이도로 부딪히는 곳에서 뒤가 이긴다.

## 실측하며 밟은 함정

- **`<img>` 의 `width`/`height` 속성은 CSS 프레젠테이션 힌트로 반영된다.** 그래서 `height` 가
  auto 가 아니게 되고 `aspect-ratio` 가 **무시된다.** 가이드 일러스트가 675px 짜리 상자 안에
  레터박스로 갇혔다. 속성은 CLS 방지를 위해 그대로 두고 CSS 에서 `height: auto` 로 푼다.
- **헤드리스 크롬은 뷰포트 폭이 약 500px 밑으로 내려가지 않는다.** `--window-size=375` 로 찍으면
  더 넓은 화면을 375px 만큼 **잘라낸** 그림이 나와 없는 가로 오버플로가 있는 것처럼 보인다.
  좁은 화면 검증은 500px 로 한다.
- **`next start` 를 백그라운드로 띄울 때 작업 디렉토리를 확인한다.** 다른 디렉토리에서 뜨면
  `NEXT_DIST_DIR` 이 맞아도 **옛 앱의 빌드를 서빙**한다. `readlink /proc/<pid>/cwd` 로 본다.

## 알려진 한계

- `frontend/` 와 코드가 **복제**되어 있다. 공통 로직(`lib/`)을 고치면 두 곳을 함께 고쳐야 한다.
  비교가 끝나면 하나를 버리는 것이 전제다 — 장기 공존을 의도한 구조가 아니다.
- 메인 외의 페이지는 기존 디자인 그대로다. 헤더·푸터·모바일 탭바도 손대지 않았다.
- **포트 3100 에서는 브라우저가 백엔드를 부르지 못한다.** 백엔드 CORS 가 `:3000` 만 허용하기
  때문이다(로그 2026-09-01). 새 메인은 전부 서버 렌더링이라 영향이 없지만, 복제된
  `/lotto/recommend`·`/dream`·`/news` 의 **버튼 동작은 3100 에서 실패한다.** 그 화면들까지
  눌러 보려면 기존 dev 서버를 내리고 3000 에 띄운다.
- 375px 실측을 하지 못했다(위 함정 참조). 500px·1280px 에서 가로 스크롤 없음을 확인했고,
  375px 에서 넘칠 수 있는 요소(히어로 볼 7개)는 `flex-wrap` 으로 접히는 것을 코드로 확인했다.
