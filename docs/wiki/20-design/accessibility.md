# 웹 접근성 체크리스트

접근성은 기능 완성 후 붙이는 것이 아니라 **첫 구현 단계부터** 반영한다. 이 페이지는 세션 C 가 컴포넌트를 만들 때마다 훑는 실행 가능한 체크리스트다. 컴포넌트별 마크업은 [[components]], 반응형·터치·모션 관련 요구는 [[responsive-rules]], 색 값은 [[design-tokens]] 를 함께 본다.

Lighthouse 접근성·SEO 점수는 세션 C 완료 기준(작업지시서 7.3)에 포함된다.

---

## 시맨틱 HTML

용도에 맞는 태그를 쓴다. `<div>` 를 남발하지 않는다.

- 페이지 최상위 콘텐츠는 `<main>` 하나.
- 헤더는 `<header>`, 내비게이션은 `<nav>`, 푸터는 `<footer>`.
- 홈의 각 구획(히어로 · 6타일 · 3분할 · 통계 · 캐러셀 · 가이드)은 `<section>` 이고, 각각 제목을 갖는다.
- 독립적으로 이해되는 카드(뉴스 항목 · 가이드 카드 · 회차 결과)는 `<article>`.
- 날짜·추첨일·D-day 는 `<time dateTime="2026-07-11">`. 기계가 읽을 수 있게 `dateTime` 을 준다.
- 목록은 `<ul>`/`<ol>`. 추천 세트·뉴스 목록·통계 순위를 `<div>` 나열로 만들지 않는다.

---

## 헤딩 계층

`h1 → h2 → h3` 순서를 건너뛰지 않는다.

- 페이지당 `<h1>` 은 하나. 홈에서는 히어로 헤드라인이 `<h1>`.
- 각 `<section>` 의 제목은 `<h2>`(예: "주요 통계", "오늘의 추천 번호", "로또 가이드").
- 카드 내부 소제목은 `<h3>`.
- 시각적으로 제목을 숨겨야 하는 구획(예: 아이콘 6타일 그리드)에도 스크린리더용 제목을 두고 `.sr-only` 로 감춘다. 계층을 비우지 않는다.

---

## ARIA — 언제 쓰고 언제 안 쓰나

**기본 시맨틱으로 충분하면 ARIA 를 쓰지 않는다.** `<button>` 에 `role="button"` 을 붙이지 않는다. ARIA 는 네이티브 시맨틱이 부족한 상호작용에만 더한다.

쓰는 곳:

- 햄버거·검색 토글 버튼: `aria-expanded`(열림 상태) + `aria-controls`(여는 대상 id).
- 현재 페이지 nav 링크: `aria-current="page"`.
- 탭 UI(통계 window 전환 등): `role="tab"` / `aria-selected` / `aria-controls`.
- 비동기 상태 알림(추천 재생성 중·완료): `aria-live="polite"` 영역.
- 아이콘만 있는 버튼: `aria-label` 로 이름을 준다(예: 검색 아이콘 → `aria-label="검색 열기"`).
- 번호 볼: `aria-label="13번, 11~20 구간"` (아래 색 단독 정보 금지 참조).

안 쓰는 곳: 이미 텍스트 라벨이 보이는 버튼, 네이티브 `<nav>`/`<main>`/`<footer>`, 시맨틱 목록.

## 키보드 내비게이션

마우스 없이 전부 조작 가능해야 한다.

- 모든 상호작용 요소는 Tab 순서에 들어오고 논리적 순서를 따른다. `tabindex` 양수 값을 쓰지 않는다.
- 버튼은 `type="button"` 을 명시한다(폼 안에서 의도치 않은 submit 방지).
- `:focus-visible` 스타일을 반드시 준다. 포커스 링을 `outline: none` 으로 지우지 않는다.
- 햄버거 드로어·검색 오버레이는 열릴 때 포커스를 안으로 가두고(focus trap), `Esc` 로 닫고, 닫으면 포커스를 연 버튼으로 되돌린다.
- 캐러셀은 좌우 화살표 버튼으로 키보드 이동이 가능해야 한다. 스와이프 전용이면 안 된다.

```css
:where(a, button, input, select, [tabindex]):focus-visible {
  outline: 2px solid var(--color-primary);
  outline-offset: 2px;
}
```

## 색 대비 (WCAG AA)

본문 텍스트/배경 대비는 WCAG AA(일반 텍스트 4.5:1, 큰 텍스트 3:1) 이상.

### ★ 흰 배경만 보고 판정하지 않는다

2026-08-21 에 라이트·다크 두 모드에서 전 페이지를 실측(Lighthouse + axe)한 결과, **미달 항목이 전부 "흰 배경에서는 통과하는데 실제로 쓰이는 배경에서는 미달"** 이었다. 토큰을 정할 때 흰 배경만 계산한 것이 원인이다.

| 무엇 | 종전 | 실제 배경에서 | 조치 |
|------|------|--------------|------|
| `--color-text-muted` #6b7280 | 흰 배경 4.83 통과 | 파스텔 카드(`--svc-*-bg`) 위 **4.00** | `#626875` — 파스텔 11종 전부 4.6↑ |
| `--color-text-subtle` #98a2b3 | — | 흰 배경에서도 **2.58** | `#647188` — 중립 배경 전용으로 못박음 |
| `.trend` 배지 | — | `--color-danger` on `-soft` **3.95** | 시맨틱 4색을 짝 배경 기준으로 재산정 |
| 다크 시맨틱 4색 | 라이트 값을 그대로 씀 | danger **3.34**, info **3.64** | 다크 전용 값 신설(밝은 쪽) |
| 주요 버튼·선택 칩의 흰 글자 | 라이트 6.37 통과 | **다크에서 2.97** | `--color-on-accent` 신설(라이트 흰 / 다크 진한) |

규칙으로 남긴다.

- **토큰을 정할 때는 그 토큰이 실제로 얹히는 배경 전부를 계산한다.** 파스텔 카드·소프트 배지·채워진 버튼이 모두 다른 배경이다.
- **라이트에서 통과해도 다크에서 통과한다는 보장이 없다.** 다크는 팔레트가 통째로 뒤집힌다. Lighthouse 는 라이트로만 돌므로 **다크는 axe 로 따로 검사한다**(절차: `frontend/README.md`).
- `--color-text-subtle` 은 3차 정보(placeholder·비활성)에만 쓰고, **중립 배경(surface·bg·surface-2) 위에만** 둔다. 파스텔 위에는 `--color-text-muted`.
- 채워진 강조 배경 위 글자는 `#fff` 를 직접 쓰지 않고 **`--color-on-accent`** 를 쓴다.
- 다크 세트에서 `--color-primary` 를 밝게 올린 이유가 색 대비다 — 다만 그 색이 **버튼 배경으로도 쓰인다**는 점을 잊지 않는다(그래서 위 토큰이 필요하다).

## 색만으로 정보를 전달하지 않기 (WCAG 1.4.1) ★핵심 함정

**번호 볼의 색 구간이 정확히 이 함정이다.** 볼 색(1~10 노랑 … 41~45 초록)은 구간을 시각적으로 알려주지만, 색을 구분하지 못하는 사용자(색각 이상·저시력·흑백 출력)에게는 아무 정보가 아니다.

따라서 색은 **보조** 채널이고 정보는 항상 다른 채널로도 전달한다.

- 볼에는 **항상 숫자가 보인다.** 색 없이도 어떤 번호인지 읽힌다.
- 스크린리더에는 `aria-label="13번, 11~20 구간"` 으로 구간을 **말로** 준다([[components]] LottoBall).
- 상태 배지(크롤 성공/실패, 추첨 D-day 등)도 색만으로 구분하지 않는다. 아이콘·텍스트를 함께 둔다.
- 통계 차트의 계열 구분도 색 + 라벨/패턴을 함께 쓴다.

볼 위 숫자 대비도 여기서 나온다. **다섯 구간 전부 `--ball-fg-dark`(어두운 글자)를 쓴다.**

> ⚠ 이 문서는 오랫동안 "노랑·초록 두 구간만 미달" 이라고 적고 있었다. **틀렸다.** 2026-08-21 실측에서 흰 숫자는 다섯 색 전부 미달이었다 — 파랑 1.88 · 빨강 2.66 · 회색 2.32 · 노랑 1.62 · 초록 1.65. 어두운 숫자는 다섯 색 전부 6.28~10.32 로 통과한다. 위 원칙("볼에는 항상 숫자가 보인다. 색 없이도 어떤 번호인지 읽힌다")이 흰 숫자로는 **성립하지 않고 있었다.**

볼 **배경색**은 그대로다([[0009-official-ball-colors-over-mockup]]) — 사용자는 색만 보고 구간을 안다. 반대로 **숫자 색은 그 매핑에 아무 역할도 하지 않으므로** 바꿔도 규약을 깨지 않는다. `--ball-fg`(흰색)는 볼에 쓰지 않고 진한 서비스 타일(`--svc-*`) 위 글리프 전용이다([[design-tokens]]).

### 흐림(opacity)으로 상태를 표현하지 않는다

`opacity` 는 글자와 배경을 **함께** 바탕색 쪽으로 끌어당겨 둘의 대비를 무너뜨린다. 등수 판정 그림의 '못 맞은 볼' 이 `opacity: 0.35` 였는데 숫자 대비가 1.53~1.81 로 사실상 안 읽혔고, **0.9 까지 올려도 빨간 볼은 4.48 로 미달**이라 값 조절로 풀리는 문제가 아니었다. 지금은 `filter: grayscale(1)` 만 쓴다(5.22~9.66 통과). 더 죽이고 싶으면 대비를 지키는 다른 채널(점선 테두리 등)을 쓴다.

### 색 이외의 채널이 필요한 곳 — 실측으로 드러난 것들

- **문장 속 인라인 링크.** 링크색과 본문색의 대비가 1.31:1 이라 색맹·저시력 사용자에게는 링크가 보이지 않았다. `p` 와 `.prose` 안의 클래스 없는 링크에 밑줄을 넣는다(`base.css`). 내비게이션·카드처럼 모양으로 이미 드러나는 링크는 대상이 아니다.
- **작은 표적이 많은 그래프는 표적마다 컨트롤을 두지 않는다.** 45개 막대를 폭에 맞추면 375px 에서 막대 하나가 6~7px 다 — 터치 타겟 24×24(WCAG 2.5.8)를 **어떤 값으로도** 만족할 수 없고, 실제로 손가락으로 특정 막대를 누를 수 없다. 넓혀서 24px 를 만들면 가로 스크롤이 생겨 그 배치의 존재 이유가 사라진다. 해법은 **그래프 전체를 하나의 조작면으로 두고 포인터 x 좌표로 가장 가까운 항목을 고르는 것**이다(차트 툴팁의 표준 패턴). 조작 대상이 전폭짜리 하나뿐이라 규칙을 지키면서 호버·탭이 모두 동작한다. 마우스만으로 쓰이지 않게 **좌우 방향키**를 함께 붙이고, 값은 `aria-live` readout 이 읽어 준다. ⚠ 터치에서는 `pointerleave` 로 선택을 지우지 않는다 — 손을 떼는 순간 결과가 사라진다.
- **`<span>` 에 `aria-label` 을 붙이지 않는다.** role 없는 span 의 `aria-label` 은 ARIA 규격이 금지하고 브라우저가 무시한다 — 뜻이 아무에게도 전달되지 않으면서 통과한 것처럼 보인다. 기호는 `aria-hidden`, 뜻은 `.sr-only` 텍스트로 준다.

## reduced-motion

`@media (prefers-reduced-motion: reduce)` 를 존중한다.

- 캐러셀 자동 재생, 볼 등장 팝 애니메이션, 카드 호버 이동, 스켈레톤 시머를 끄거나 줄인다.
- CSS 뿐 아니라 JS 애니메이션도 `matchMedia('(prefers-reduced-motion: reduce)')` 로 감지해 타이머 자체를 걸지 않는다([[responsive-rules]] prefers-reduced-motion).
- 모션을 껐을 때 정보가 사라지면 안 된다. 애니메이션은 장식이지 정보 전달 수단이 아니다.

## 이미지 alt vs aria-hidden

- 의미 있는 이미지(뉴스 썸네일, 회차 판매점 사진 등)는 내용을 서술하는 `alt` 를 준다.
- 순수 장식(히어로 일러스트, 배경 그라디언트, 아이콘 타일의 글리프처럼 옆 텍스트가 이미 설명하는 것)은 `alt=""` 또는 `aria-hidden="true"` 로 접근성 트리에서 숨긴다.
- 이모지 아이콘이 유일한 의미 전달자면 `role="img"` + `aria-label` 을 주고, 옆 텍스트가 이미 있으면 `aria-hidden="true"`.
- SVG 로고: 서비스명을 담으면 `role="img"` + `<title>`, 텍스트 로고 옆 장식이면 `aria-hidden`.

빈 `alt` 를 빠뜨려 파일명이 읽히는 일이 없게 한다 — 장식 이미지에도 `alt=""` 를 명시한다.
