# 애드센스 승인 전 체크리스트

애드센스 통과를 보장할 수는 없다. 다만 아래 기준을 충족하면 심사에서 불리할 가능성을 줄인다(초안 11장). **승인 전에는 광고를 넣지 않는다.** 광고 코드는 콘텐츠 최소 기준을 충족하고 정책 페이지가 준비된 뒤에 삽입한다.

핵심 정책은 서비스 포지셔닝과 직결된다: 이 사이트는 "당첨 예측 사이트"가 아니라 "정보형 대시보드"다(초안 20장). 금지 표현은 [[forbidden-expressions]], 메타·본문 렌더링은 [[metadata-strategy]] 를 본다.

---

## 1. 필수 정책 페이지 4종 (초안 11.1)

MVP 에 다음 4개를 포함한다. 신청 전 실제 콘텐츠가 채워져 있어야 한다.

- [ ] `/privacy` — 개인정보처리방침
- [ ] `/terms` — 이용약관
- [ ] `/disclaimer` — 면책 고지
- [ ] `/contact` — 문의

개인정보처리방침에 포함할 내용:

- [ ] 수집하는 정보 / 수집 목적 / 보유 기간
- [ ] 쿠키 사용 여부
- [ ] **Google AdSense 및 제3자 광고 사업자의 쿠키 사용 가능성**
- [ ] 광고 개인화 관련 안내
- [ ] 사용자의 선택권
- [ ] 문의처

로그인이 없어도 서버 로그·쿠키·광고 식별자·GA·애드센스로 인해 개인정보/쿠키 안내가 필요하다(초안 11.1). 애널리틱스 도입 사실도 방침에 반영한다([[analytics]]).

---

## 2. 콘텐츠 최소 기준 (초안 11.2)

신청 전 다음 규모를 확보한다.

- [ ] 회차 상세 페이지 **20개 이상**
- [ ] 통계 상세 페이지 **3~5개 이상**
- [ ] 가이드 페이지 **5~10개 이상**
- [ ] 꿈해몽 키워드 페이지 **10개 이상**
- [ ] 뉴스/큐레이션 페이지 1개 이상
- [ ] 메인홈·로또 대시보드에 충분한 본문 설명

피해야 할 상태(초안 11.2·17장):

- API 데이터만 표로 출력하는 페이지
- 뉴스 제목만 복사해 나열
- 아이콘만 있는 메인홈
- 빈 페이지·"준비 중" 페이지 다수
- 광고 영역이 콘텐츠보다 많은 페이지
- 중복 템플릿만 반복되는 회차 페이지

이 기준이 [[metadata-strategy]] 의 "본문은 서버 렌더링" 원칙과 만난다. 회차·통계·추천·꿈해몽 페이지 모두 **API 표 위에 해석 본문**이 있어야 한다(초안 8장). 회차 페이지는 회차별 차별화 문장을 자동 생성하거나 보강한다.

## 3. 복권/도박 리스크 관리 (초안 11.3)

복권 콘텐츠는 광고 제한 주제로 분류될 수 있다. 다음을 지킨다.

**금지**

- [ ] 온라인 복권 구매 유도
- [ ] 복권 구매 대행
- [ ] 유료 번호 판매
- [ ] 당첨 보장 / 고확률 / 1등 예측 표현 ([[forbidden-expressions]])
- [ ] 카지노·도박 사이트 제휴 링크
- [ ] 구매 버튼 / 결제 유도

**권장**

- [ ] 공식 당첨결과 확인
- [ ] 회차별 데이터 정리
- [ ] 번호 통계 분석
- [ ] 재미용 번호 추천(면책 명시)
- [ ] 건전한 복권 이용 안내
- [ ] 19세 미만 구매 불가 안내 / 책임 있는 이용 안내

## 4. 광고 배치 기준 (초안 11.4)

승인 후에도 지킨다.

- [ ] 광고가 콘텐츠를 가리지 않는다.
- [ ] 버튼·메뉴·번호 생성 영역 바로 옆에 오해되게 배치하지 않는다.
- [ ] 광고가 내비게이션·액션 버튼처럼 보이지 않는다.
- [ ] 콘텐츠보다 광고가 많아 보이지 않는다.
- [ ] 추천번호 생성 버튼 주변에 광고를 과도하게 배치하지 않는다.

## 5. 구현 규칙

### 5.1 승인 전 광고 미렌더링

`NEXT_PUBLIC_ADSENSE_CLIENT` 가 **비어 있으면 광고 컴포넌트가 아무것도 렌더링하지 않는다**(보완판 6.5). 승인 전까지 이 변수를 공란으로 두면 코드가 이미 있어도 광고가 나가지 않는다.

```tsx
// app/components/AdSlot.tsx
"use client";
import { useEffect } from "react";

const CLIENT = process.env.NEXT_PUBLIC_ADSENSE_CLIENT;

export function AdSlot({ slot }: { slot: string }) {
  if (!CLIENT) return null; // 승인 전: 아무것도 렌더링하지 않음

  useEffect(() => {
    try {
      // @ts-expect-error adsbygoogle 전역
      (window.adsbygoogle = window.adsbygoogle || []).push({});
    } catch {}
  }, []);

  return (
    // CLS 방지: 슬롯 높이를 미리 예약
    <div style={{ minHeight: 280 }}>
      <ins
        className="adsbygoogle"
        style={{ display: "block" }}
        data-ad-client={CLIENT}
        data-ad-slot={slot}
        data-ad-format="auto"
        data-full-width-responsive="true"
      />
    </div>
  );
}
```

애드센스 로더 스크립트도 `next/script` 의 `strategy="afterInteractive"` 로 로드한다([[analytics]] 와 같은 원칙 — `beforeInteractive` 는 LCP 를 해친다). 로더 역시 `NEXT_PUBLIC_ADSENSE_CLIENT` 가 있을 때만 렌더링한다.

### 5.2 CLS 방지 슬롯 예약 — **승인 후에만**

광고 슬롯은 `min-height`(또는 `aspect-ratio`)를 예약해 광고가 늦게 로드돼도 레이아웃이 밀리지 않게 한다(보완판 5.3·6.5). CLS 는 Core Web Vitals 이자 SEO 요소다.

> **정정 (2026-07-09).** 이 예약을 **미승인 상태에도 적용하지 않는다.** 광고가 없으면 늦게 도착할 것도 없어 CLS 가 발생하지 않는다. 남는 것은 콘텐츠 사이의 200px 짜리 빈 구멍뿐이고, 승인은 몇 달 뒤일 수 있다. 승인 시점에는 어차피 `NEXT_PUBLIC_ADSENSE_CLIENT` 를 넣고 다시 빌드하므로 그때 자리가 생긴다. 실제로 이 예약이 홈의 "주요 통계 ↔ 오늘의 추천 번호" 사이를 벌려 놓았다.
>
> 즉 `AdSlot` 은 미승인 시 `null` 을 반환한다. 빈 `<div class="ad-slot">` 도 남기지 않는다 ([[components]]).

### 5.3 "준비 중" 페이지 광고 금지

연금복권·스피또 등 "준비 중" 페이지에는 **광고를 렌더링하지 않는다**(초안 3장·17장). 빈 페이지·공사 중 페이지에 광고를 노출하면 심사에 부정적이다. `AdSlot` 을 이런 페이지에 배치하지 않는다.

### 5.4 ads.txt 는 승인 후

`public/ads.txt` 는 **승인 후** 발급된 퍼블리셔 ID 로 추가한다(보완판 6.5). 승인 전에 미리 만들지 않는다.

## ★ 자동 광고와 렌더링 방식 — 2026-09-01 전수 점검

### 사실 정정: **자동 광고는 SSG 를 요구하지 않는다**

"자동 광고를 쓰려면 분석 페이지가 SSG 여야 한다" 는 말이 돌지만 사실이 아니다. 자동 광고가 요구하는 것은 렌더링 방식이 아니라 **AdSense 크롤러(`Mediapartners-Google`)가 페이지 본문을 읽을 수 있는가** 하나다.

- **SSG · ISR · SSR 은 모두 서버가 완성된 HTML 을 준다** — 크롤러가 읽는다.
- 문제가 되는 것은 **CSR 뿐**이다. 빈 껍데기를 받으면 크롤러가 "콘텐츠 없음" 으로 보고 광고를 붙이지 않거나 심사에서 떨어진다.

우리는 애초에 "JS 를 꺼도 본문이 보인다" 를 완료 기준으로 두었으므로([[metadata-strategy]]) 이 요건을 이미 만족한다.

### 전수 실측 (JS 없이 받은 HTML 의 본문 글자 수)

| 구간 | 페이지 | 본문 |
|---|---|---|
| 두꺼움 | `/lotto/stat*` | 48,000~50,000자 |
| 보통 | `/`, `/lotto/latest`, `/dream/*`, `/lotto/recommend` | 2,400~5,900자 |
| 얇음 | `/lotto/round/*`, `/news`, `/videos/*` | 1,400~1,800자 |
| **가장 얇음** | `/guide`(1,060) · `/contact`(1,054) | ⚠ 아래 참조 |

**동적 렌더링(`ƒ`)인 `/news` · `/videos` · `/videos/[id]` 도 본문이 나온다** — SSR 이기 때문이다. SSG 로 바꿀 이유가 없다.

### ⚠ 자동 광고는 로더 하나만 있으면 **페이지 어디든** 붙는다

수동 슬롯(`AdSlot`)을 두지 않은 것만으로는 막히지 않는다. 그래서 **로더를 어디에 두는가가 곧 광고 정책**이다.

2026-09-01 에 발견해 고쳤다 — 로더가 `AnalyticsScripts` 안에 있어 **루트 레이아웃을 통해 운영자 화면(`/admin`)에도 들어갔다.** 계약이 그 화면에 "광고를 넣지 않는다" 고 정했는데, 자동 광고를 켜는 순간 어겨질 상태였다. `AdSenseLoader` 로 떼어 내 **공개 셸(`app/(site)/layout.tsx`)에서만** 부른다.

> 애널리틱스는 루트에 남겨도 된다. 광고와 달리 운영자 화면에서 도는 것이 문제가 아니다.

### 남은 관찰 — 코드 밖에서 처리할 것

| 항목 | 상태 | 조치 |
|---|---|---|
| `/guide`(1,060자) · `/contact`(1,054자) | 자동 광고가 붙는다 | **AdSense 대시보드에서 URL 제외**하거나 콘텐츠를 보강한다. "콘텐츠 대비 광고 과다" 판정 위험 |
| `/news` · `/videos` 가 동적 | 백엔드 장애 시 **크롤러가 빈 페이지를 본다** | 렌더링 방식의 문제가 아니라 데이터 가용성의 문제다. 심사 기간에는 백엔드가 떠 있어야 한다 |
| `/lotto/stat*` 에 수동 슬롯 없음 | 본문이 가장 두꺼운데 슬롯이 없다 | 표·차트가 빽빽해 수동 자리가 애매하다. **자동 광고에 맡긴다** |

### 확인된 것

- 로더·슬롯 모두 `NEXT_PUBLIC_ADSENSE_CLIENT` 가 비면 **완전 미렌더링**(승인 전 규칙 5.1). 가짜 client 로 켜서 실측했다.
- `.ad-slot { min-height: 100px }` 로 자리를 예약해 **CLS 0**.
- `robots.txt` 가 `Mediapartners-Google` · `AdsBot-Google` 을 막지 않는다([[crawling-defense]] 실측).
- 정책 페이지 4종(이용약관·개인정보처리방침·면책 고지·문의) 모두 실제 본문으로 존재한다.

## 전면 광고(Vignette) — 2026-09-01 조사

사용자가 원한 것은 밀도형 자동 광고가 아니라 **"페이지를 옮기면 광고가 뜨고 닫기를 눌러 닫는"** 형태다. 그 형식의 이름과, 우리 구조에서 그것이 되는지를 조사했다.

### 이름부터

| 부르는 이름 | 실제 형식 | 어디서 켜는가 |
|---|---|---|
| 사용자가 말한 "자동 광고" | **전면 광고(Vignette / Interstitial)** | AdSense 대시보드 → 광고 → 자동 광고 → **광고 형식** |
| — | 앵커 광고(화면 가장자리 고정) | 같은 자리 |
| — | 인페이지 광고(본문 사이 밀어 넣기) | 같은 자리 |

셋 다 **자동 광고 한 묶음 안의 개별 형식**이고, **각각 따로 켜고 끌 수 있다.** 즉 "인페이지는 끄고 전면 광고만 켜기" 가 대시보드에서 가능하다 — **광고를 과하지 않게 두면서 전면 광고만 쓰겠다** 는 요구는 형식 선택으로 달성된다. 코드로 할 일은 없다. 로더(`AdSenseLoader`)만 있으면 되고 이미 붙어 있다.

### ⚠ 그런데 우리 사이트에서는 거의 뜨지 않는다

**전면 광고는 브라우저의 실제 페이지 이동(document 로드)을 신호로 뜬다.** 우리는 Next.js App Router 이고 내부 이동은 전부 `next/link` 클라이언트 라우팅이다(2026-09-01 기준 36개 파일). 링크를 눌러도 document 가 새로 로드되지 않으므로 **애드센스는 페이지가 바뀐 것을 모른다.**

> 이것은 [[analytics]] 에 적힌 GA4 함정과 **정확히 같은 구조**다. GA4 도 같은 이유로 최초 진입만 집계돼 `usePathname()` 수동 전송을 붙였다. 다른 점은, GA4 는 우리가 부를 API(`gtag('event','page_view')`)가 있지만 **자동 광고의 전면 광고는 우리가 부를 수 있는 API 가 없다** — 스크립트가 스스로 판단한다.

따라서 실제로는 이렇게 된다.

| 이동 | 전면 광고 |
|---|---|
| 외부에서 우리 페이지로 처음 들어옴 | 뜰 수 있다 |
| 사이트 안에서 링크 클릭 | **뜨지 않는다** |
| 브라우저 뒤로/앞으로 | 뜨지 않는다 |

사용자가 그린 시나리오 — "번호추천에서 분석을 눌러 페이지가 이동하면 광고가 뜬다" — 는 **정확히 뜨지 않는 쪽**이다.

### 뜨게 하려면 — 대가가 있다

그 링크만 `<Link>` 대신 평범한 `<a href>` 로 두면 document 가 새로 로드되어 전면 광고가 뜬다. 대가는 **그 이동이 느려지는 것**이다(JS 번들·CSS 재다운로드, 체감 0.3~1초). 사이트 전체에 적용하면 App Router 를 쓰는 의미가 사라진다.

**권장: 한두 곳만 고른다.** 광고를 보여주기에 가장 자연스러운 지점은 "사용자가 결과를 기다리는 것을 이미 받아들인" 이동이다.

### ⚠ 앵커 광고와 모바일 하단 바로가기 바는 공존할 수 없다

`MobileTabBar`(`z-index: 40`)는 모바일에서 화면 하단에 고정된다. **앵커 광고도 하단에 고정되고, 애드센스가 붙이는 `z-index` 는 우리가 이길 수 있는 값이 아니다.** 앵커 광고를 켜면 바로가기 바가 가려진다 — 게다가 게시자 정책이 금지하는 **"탐색 요소를 덮는 광고"** 에 그대로 해당한다.

→ **둘 중 하나만 쓴다.** 바로가기 바는 사용자가 요청한 기능이므로 **앵커 광고는 켜지 않는 쪽을 권한다.**

### ⚠ 진행 팝업(`SimulatorRunner`) 안에는 광고를 넣지 않는다

"AI가 번호를 추천 중" 팝업이 15초쯤 도는 동안 광고를 넣으려던 계획이 있었다. **철회한다.** 셋이 걸린다.

1. 게시자 정책이 **광고가 콘텐츠를 덮거나 콘텐츠가 광고를 덮는 배치**를 금지한다. 이 팝업은 정의상 페이지를 덮는다.
2. 바로 아래가 **'그만두기' 버튼**이다. 조작 요소에 인접한 광고는 의도치 않은 클릭 유발로 본다.
3. 기술적으로도, 팝업이 열릴 때 `adsbygoogle.push({})` 를 부르면 **페이지에 이미 떠 있던 광고까지 다시 로드**된다.

`.sim-slot` 은 광고 자리가 아니라 **여백**으로 남겼다(코드 주석에 근거를 적어 뒀다).

### 사용자가 결정할 것

| 결정 | 선택지 |
|---|---|
| 전면 광고를 쓸 것인가 | 쓴다면 어느 이동을 하드 내비게이션으로 바꿀지 지정한다(한두 곳) / 안 쓴다면 지금 수동 슬롯 6곳 + 인페이지 자동 광고로 충분하다 |
| 앵커 광고 | **켜지 않기를 권한다**(모바일 바로가기 바와 충돌) |
| 인페이지 자동 광고 | "과하지 않게" 를 원하므로 **끄고 수동 슬롯 6곳만 쓰는 것**도 선택지다 |

> ⚠ 위 정책 해석은 **조사 결과이지 법적 판단이 아니다.** 실제 적용 여부는 사용자가 정한다.

## 광고를 켜기 전에 미리 고쳐 둔 것 — 2026-09-01

"지금 광고를 넣지는 않지만, 나중에 켤 것을 전제로 고칠 것은 다 고쳐 달라"는 요청으로 한 작업이다. **승인 후 코드를 다시 손대지 않아도 되게** 하는 것이 목표였다.

### ★ 발견한 버그 — 지금 켰다면 광고가 한 개도 안 나왔다

`<AdSlot slot="home-mid" />` 가 `data-ad-slot="home-mid"` 를 그대로 내보내고 있었다. 애드센스가 요구하는 값은 **대시보드에서 광고 단위를 만들 때 발급되는 숫자 ID** 다. 사람이 읽는 이름은 아무 의미가 없다.

증상이 "광고가 안 나온다" 뿐이라 **원인이 코드 어디에도 드러나지 않았을 것**이다. 승인 직후 가장 헤맬 만한 자리였다.

고친 방식: 이름은 코드에 두고(배치는 지금 정할 수 있다) **숫자는 환경변수로 받는다**(`NEXT_PUBLIC_ADSENSE_SLOTS`). 숫자가 없는 자리는 그 자리만 렌더링되지 않는다.

### 고친 목록

| # | 고친 것 | 왜 |
|---|---|---|
| 1 | 슬롯 이름 → 실제 ID 매핑(`lib/ad-slots.ts`) | 위 버그. 이름만으로는 광고가 안 나온다 |
| 2 | `<aside aria-label="광고">` + 보이는 '광고' 라벨 | 광고는 iframe 안이라 스크린리더가 못 읽는다. 바깥에서 정체를 알려야 한다. 정책도 라벨을 **'광고'·'스폰서 링크' 로만** 허용한다 |
| 3 | 안 채워진 광고 자리 접기 | `data-ad-status="unfilled"` 면 본문 한가운데 **'광고' 라벨이 붙은 빈 100px 구멍**이 남는다. 신생 사이트일수록 잦다 |
| 4 | `/ads.txt` 라우트 | 없으면 입찰이 걸러져 단가가 떨어진다. 승인 후 첫 경고 항목이다 |
| 5 | 정책·얇은 페이지에서 로더 제외 | 자동 광고는 로더만 있으면 어디든 붙는다. 슬롯을 안 둔 것으로는 안 막힌다 |
| 6 | `AdBreakLink` | 전면 광고가 뜰 수 있는 이동을 미리 표시해 둔다 |
| 7 | 중복 `push({})` 방어 | 이미 채워진 `ins` 에 다시 밀면 애드센스가 오류를 남긴다 |

### `/ads.txt` — 왜 정적 파일이 아니라 라우트인가

퍼블리셔 ID 를 **두 곳에 적지 않기 위해서**다. `public/ads.txt` 에 손으로 적으면 `.env_frontend` 와 한쪽만 고치는 사고가 난다. **틀린 ads.txt 는 없는 것보다 나쁘다** — 선언되지 않은 판매자로 취급되어 인벤토리가 통째로 무효가 된다. 그래서 `NEXT_PUBLIC_ADSENSE_CLIENT`(`ca-pub-…`)에서 `ca-` 를 떼어 파생시키고, 승인 전에는 **404** 를 낸다.

### 광고를 붙이지 않는 경로

`/terms` `/privacy` `/disclaimer` `/contact` `/guide`(허브만) `/admin`.

정책 페이지는 심사가 존재를 확인하는 페이지이고, 개인정보처리방침에 광고 쿠키가 도는 것은 앞뒤가 맞지 않는다. `/guide` 허브(1,060자)와 `/contact`(1,054자)는 "콘텐츠 대비 광고 과다" 판정의 표적이다. **하위 가이드 글은 본문이 충분해 제외하지 않는다**(실측: `/guide/lotto-rule` 로더 있음).

⚠ **완전한 차단은 아니다.** 클라이언트 라우팅으로 넘어오면 로더는 이미 로드된 뒤다. 막히는 것은 **직접 진입**(검색·외부 링크·크롤러)이고, 애드센스 크롤러는 URL 을 직접 방문하므로 심사 관점에서는 이쪽이 중요하다. **대시보드에서도 같은 URL 을 제외**해 두 겹으로 막는다.

### `AdBreakLink` — 전면 광고가 뜰 수 있는 이동

광고가 **꺼져 있으면 `<Link>`, 켜져 있으면 `<a>`** 다. 즉 지금은 동작이 완전히 같고, 환경변수를 채우는 순간 그 자리들만 하드 내비게이션으로 바뀐다.

현재 적용: **`StatNav`** (통계 3종 이동 카드). "분석 화면으로 깊이 들어가는 이동"이라 잠깐의 로딩이 어색하지 않다. 더 붙이고 싶으면 회차 상세·영상 상세가 다음 후보이나, **늘릴수록 사이트가 느려진다** — 한두 곳으로 유지하기를 권한다.

### 실측 (가짜 `ca-pub-0000000000000000` 으로 빌드)

| 항목 | 결과 |
|---|---|
| `/ads.txt` | 광고 켬 → `google.com, pub-0000000000000000, DIRECT, f08c47fec0942fa0` / 광고 끔 → **404** |
| 로더 | 공개 9개 페이지 **있음**, `/terms` `/privacy` `/disclaimer` `/contact` `/guide` `/admin` **없음**, `/guide/lotto-rule` **있음** |
| `data-ad-slot` | 6곳 모두 **숫자** ID |
| 광고 끈 상태 | 8개 페이지에서 광고 흔적 **0회** (회귀 없음) |
| 하드 내비게이션 | 광고 켬 → **문서 재로드** / 광고 끔 → **클라이언트 라우팅** |
| axe WCAG 2.2 AA | 6페이지 × 라이트·다크 **위반 0건** |
| 375px 가로 넘침 | 5페이지 **0** |

> ⚠ 검증 중 **옛 테스트 서버가 포트를 잡고 있어 측정이 한 번 거짓이었다.** `next start` 는 `next-server` 로 프로세스명이 바뀌어 `pkill -f "next start"` 에 걸리지 않는다. 포트로 확인하고 죽여야 한다(`ss -tlnp`). 또 `.next-prod` 를 지우지 않고 재빌드하면 **빌드 캐시가 옛 `NEXT_PUBLIC_*` 치환 결과를 재사용**한다 — 환경변수를 바꿔 실측할 때는 반드시 지운다.

### 사용자가 승인 후에 할 일

1. `.env_frontend` 에 `NEXT_PUBLIC_ADSENSE_CLIENT` 와 `NEXT_PUBLIC_ADSENSE_SLOTS` 를 채우고 **다시 빌드**한다(`NEXT_PUBLIC_*` 은 빌드 시점에 박힌다).
2. 대시보드 **자동 광고 → 광고 형식**에서 전면 광고만 켜고 **앵커 광고는 끈다**(모바일 바로가기 바와 충돌).
3. 대시보드에서 위 "광고를 붙이지 않는 경로"를 **URL 제외**로도 등록한다.
