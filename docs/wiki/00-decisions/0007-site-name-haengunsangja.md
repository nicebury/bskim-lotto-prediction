# ADR 0007 — 사이트명은 "행운상자"

## 결정

사이트명을 **행운상자**로 한다. 당초 후보였던 "행운복권상자" 를 쓰지 않는다.

코드 어디에도 사이트명을 하드코딩하지 않는다. `NEXT_PUBLIC_SITE_NAME` 한 곳에서만 관리한다 ([[env-vars]]).

## 맥락

초안은 "로또인사이트" 라는 가칭을 썼다. 사용자가 "행운복권상자" 를 제안했고, 명칭 충돌과 리스크를 조사한 뒤 "행운상자" 로 확정했다.

## 왜 "복권" 을 빼는가

**판매 사이트로 오인될 위험 때문이다.**

국내에서 복권 판매는 기획재정부 복권위원회가 지정한 동행복권(dhlottery.co.kr)이 **유일한 합법 채널**이다. 그리고 동행복권을 사칭하는 사기 사이트가 늘고 있다 ([보도](https://www.ohmynews.com/NWS_Web/View/at_pg.aspx?CNTN_CD=A0003176306)). 이용자도 규제기관도 이 문제에 민감하다.

이름에 "복권" 이 들어가면 검색 결과와 브라우저 탭에서 판매 사이트처럼 읽힌다. 초안 2장이 명시한 "복권 구매 대행처럼 보이면 안 된다" 와 17장의 금지사항이 정확히 이 지점을 겨냥한다. 사이트 안의 문구를 아무리 조심해도, 이름 자체가 첫인상을 만든다.

**애드센스 심사에도 불리하다.** 복권 콘텐츠는 광고 제한 주제로 분류될 수 있다. 심사자가 보는 첫 화면의 로고에 "복권" 이 있고 사이트가 로또 번호를 생성한다면, 정보형 대시보드라는 포지션을 설명하는 데 불필요한 부담을 진다.

**"행운" 만으로도 브랜드 정체성은 유지된다.** 잃는 것은 이름 안의 키워드 하나이고, 얻는 것은 정책 리스크의 감소다.

## 명칭 충돌 조사

**"행운상자" 와 동일한 서비스·도메인은 발견되지 않았다.** 아이템매니아의 이벤트명("매니아 행운 상자") 용례가 있으나 서비스명 충돌이 아니다.

참고로 "행운복권" 이라는 이름의 로또 앱이 구글 플레이에 이미 존재한다. "행운복권상자" 를 택했다면 앞 네 글자가 겹쳐 검색 결과에서 섞였을 것이다.

## 남는 약점

**"행운상자" 는 일반명사 조합이라 브랜드 검색 유입이 약하다.** 누구도 "행운상자" 를 검색하지 않는다.

이것은 감수한다. 초안 12.3 이 이미 유입 전략을 회차·통계 롱테일 키워드(`로또 1231회 당첨번호`, `로또 오래 안 나온 번호`, `돼지꿈 로또번호`)로 설계했기 때문이다. 사이트명 자체로는 트래픽을 기대하지 않는다. 브랜드 검색은 서비스가 알려진 뒤의 문제다.

## 미확인 — 사람이 해야 하는 일

- [ ] **KIPRIS(kipris.or.kr) 상표 검색** — 제9류(앱), 제35류(광고업), 제41류(오락·게임 서비스업)
- [ ] 도메인 확보 (`.com` / `.kr`)

상표 등록 여부는 웹 검색으로 확정할 수 없다. 이 두 항목이 끝날 때까지 이 ADR 의 `tbd` 태그를 유지한다. 조사 결과는 [[trademark-check]] 에 기록한다.

## 되돌리려면

상표 충돌이 발견되면 즉시 바꾼다. `NEXT_PUBLIC_SITE_NAME` 한 곳만 고치면 되도록 설계한 이유가 이것이다. 다만 도메인을 확보하고 검색엔진에 등록한 뒤에는 비용이 급격히 커진다 — **도메인 구매 전에 KIPRIS 조사를 끝낸다.**
