# ADR 0009 — 볼 색상은 공식 규칙을 따른다

## 결정

번호 볼의 색상은 동행복권 공식 5구간 규칙을 따른다. `docs/raw/메인샘플.png` 의 볼 색상을 **채택하지 않는다.**

| 구간 | 색 |
|------|-----|
| 1~10 | 노랑 |
| 11~20 | 파랑 |
| 21~30 | 빨강 |
| 31~40 | 회색 |
| 41~45 | 초록 |

시안은 **레이아웃과 톤앤매너의 참조**로만 쓴다. 픽셀 사양이 아니다.

## 맥락

시안(`docs/raw/메인샘플.png`)의 최신 회차 카드는 볼을 이렇게 칠했다.

| 번호 | 시안 색 | 공식 규칙 |
|------|--------|----------|
| 5 | 노랑 | 노랑 ✓ |
| 11 | **초록** | 파랑 |
| 18 | **파랑** | 파랑 ✓ |
| 27 | **노랑** | 빨강 |
| 33 | **초록** | 회색 |
| 42 | **회색** | 초록 |

여섯 개 중 넷이 어긋난다. 시안 디자이너가 구간 규칙을 모른 채 색을 배분한 것으로 보인다.

## 왜 시안을 따르지 않는가

**색-구간 매핑이 학습된 관습이기 때문이다.**

동행복권 공식 사이트를 포함해 국내의 모든 로또 정보 사이트가 이 다섯 색을 쓴다. 로또를 몇 번 본 사람은 노란 볼을 보면 한 자리 수임을, 초록 볼을 보면 41 이상임을 색만으로 안다. 숫자를 읽기 전에 안다.

이 매핑을 깨면 두 가지를 잃는다. 첫째, 사용자가 우리 사이트에서만 다시 학습해야 한다. 둘째 — 그리고 더 중요하게 — **다른 사이트에서 온 사용자가 우리 데이터를 의심한다.** 색이 다르다는 것은 "이 사이트는 로또를 잘 모른다" 는 신호다. 정보형 대시보드에게 신뢰는 유일한 자산이다.

디자인 시안의 가치는 레이아웃, 여백, 색조, 카드의 위계에 있다. 그것들은 채택한다. 볼 색상은 시안이 정할 사항이 아니라 도메인이 정하는 사항이다.

## 기존 구현과의 일관성

기존 `frontend/src/components/LottoBall.jsx:1-7` 은 이미 공식 규칙을 구현하고 있다.

```jsx
n <= 10 → range-1    n <= 20 → range-2    n <= 30 → range-3
n <= 40 → range-4    else    → range-5
```

신규 프론트도 같은 경계를 쓴다. 클래스 이름과 토큰은 [[design-tokens]] 에 있다.

## 접근성 — 색만으로 정보를 전달하지 않는다

이 결정에는 함정이 따라온다.

**증상.** 색각 이상 사용자에게 21~30 구간(빨강)과 41~45 구간(초록)이 구분되지 않는다. 적록색약은 한국 남성의 약 5%다.

**원인.** 구간 정보를 색이라는 단일 채널로만 전달했다. WCAG 1.4.1(Use of Color) 위반이다.

**해법.** 볼에는 **항상 숫자가 표시된다** — 숫자가 1차 정보다. 색은 보조 채널이다. 그리고 스크린리더용 `aria-label` 에 구간을 명시한다.

```
aria-label="13번, 11~20 구간"
```

색을 지워도 화면이 여전히 이해 가능해야 한다. 그것이 이 규칙의 시험이다. 자세한 것은 [[accessibility]].

또 하나: 노랑(`#FBC400`)과 초록 볼 위의 흰 글씨는 대비가 부족하다. 밝은 볼에는 어두운 전경색을 쓴다 ([[design-tokens]] 의 `--ball-fg-dark`).

## 되돌리려면

되돌리지 않는다. 시안을 갱신해야 한다면 디자이너에게 공식 규칙을 전달한다.
