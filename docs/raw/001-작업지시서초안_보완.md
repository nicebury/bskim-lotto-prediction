## 1장. 현재 상태와 목표 상태

### 1.1 현재

```
backend/   FastAPI 모노리식 — 크롤러 + 예측 + 꿈해몽 + 웹API 가 한 프로세스
           SQLite (journal_mode=DELETE), APScheduler 주간 크론 내장
frontend/  Vite + React 18 plain JSX, CSR SPA
```

### 1.2 목표

```
worker/ 배치 수집 전용. 잡별 독립 스케줄 + 수동 트리거. Postgres write 소유
backend/   웹 API 전용. Postgres read-only. 예측·꿈해몽 계산
frontend/  Next.js App Router. SSR/SSG/ISR
```

### 1.3 자산 처리 대장

| 현재 위치 | 처리 | 이동/폐기 사유 |
|-----------|------|---------------|
| `backend/app/crawler.py` | → `worker/` 이동 | 수집 책임 |
| `backend/app/naver_source.py` | → `worker/` 이동 | 수집 책임 |
| `backend/app/scheduler.py` | → `worker/` 이동 + **잡 레지스트리로 일반화** | 잡별 크론이 달라짐 |
| `backend/scripts/seed_from_github.py` | → `worker/` 이동 + Postgres 대응 개작 | |
| `backend/app/prediction/**` | **그대로 유지** (backend) | numpy 단일 의존, 순수 계산 |
| `backend/app/dream/**` | **그대로 유지** (backend) | ChromaDB 읽기 |
| `backend/data/chroma_words/` | **그대로 유지** | pgvector 이관하지 않음 |
| `backend/data/lotto.db` | 1회 이관 후 보관 | Postgres 로 |
| `backend/app/database.py` (aiosqlite) | 폐기 → psycopg | |
| `frontend/**` | **신규 완성 후 전체 삭제** | Next.js 로 재작성 |

> `frontend/` 는 신규 프론트가 완성될 때까지 **그대로 둔다.** 참조용으로 쓰되 수정하지 않는다. 삭제 시점은 Phase 3 완료 후 사용자 확인을 거친다.

**설계 근거 (요구사항 13 — 배포·유지보수 고려)**

- 모노레포 유지: 세션 간 계약(DB 스키마·API)이 한 커밋에서 검증된다. 별도 저장소면 계약 변경이 두 PR로 쪼개져 정합성이 깨지기 쉽다.

## 3장. 문서 계층 규약 ★핵심

요구사항 1(메인 CLAUDE.md 간결), 2(세션별 CLAUDE.md), 3(README 분리), 4(위키) 를 하나의 규칙으로 통합한다.

### 3.1 판정 기준

> **어기면 안 되는 것 → CLAUDE.md**
> **찾아보면 되는 것 → README.md / Wiki**

CLAUDE.md 는 매 턴 컨텍스트에 강제 주입된다. 여기에 실행 명령어나 설계 설명을 넣으면 모든 턴에서 토큰을 낭비하고, 정작 중요한 규칙이 묻힌다.

### 3.2 역할 분담표

| 문서 | 담는 것 | 담지 않는 것 | 분량 상한 |
|------|---------|-------------|----------|
| 루트 `CLAUDE.md` | 전 세션 공통 불변 규칙: `.env` 열람 금지, 한국어 사용, 커밋 규약, 세션 경계 침범 금지, 위키 참조 지시 | 스택·포트·명령어·설계 근거 | **40줄** |
| 세션 `CLAUDE.md` | 그 세션이 **매 턴 지켜야 할 제약**: 소유/비소유 경계, 금지 표현, 계약 준수 의무, 참조할 위키 페이지 경로 | 실행법·트러블슈팅·역사 | **60줄** |
| 세션 `README.md` | 실행 명령, 포트, 의존성 설치, 스모크 테스트, 트러블슈팅, 디렉토리 안내 | 규칙(위반 시 문제되는 것) | 자유 |
| `docs/wiki/**` | 설계 근거, 계약 명세, 절차, 의사결정 기록(ADR) | 매 턴 필요한 제약 | 페이지당 **200줄** |

### 3.3 루트 `CLAUDE.md` 에 반드시 들어갈 항목 (내용 고정)

1. 모든 응답과 문서는 **한국어**로 작성한다.
2. **`.env` 파일을 절대 읽지 않는다.** 환경변수 정보가 필요하면 `env.sample` 을 읽는다. 새 변수가 필요하면 `env.sample` 에 키와 주석만 추가하고 사용자에게 `.env` 갱신을 요청한다. (요구사항 5)
3. 자기 세션 디렉토리 밖의 코드를 수정하지 않는다. 다른 컴포넌트가 필요하면 `docs/wiki/10-contracts/` 의 계약을 읽는다.
4. 설계·절차·결정은 `docs/wiki/` 에서 찾는다. 없으면 위키에 먼저 기록하고 개발한다.
5. 서비스 성격상 금지된 표현(당첨 확률, 고확률, 예상 적중률, 1등 보장 등 — 초안 8.3·17장)을 코드·주석·UI 문구 어디에도 쓰지 않는다.
6. 커밋 메시지는 한국어. `feat:` / `fix:` / `docs:` / `chore:` 접두어.

> 위 6개 외의 것은 루트 `CLAUDE.md` 에 넣지 않는다. 현재 저장소의 `CLAUDE.md`(약 200줄, 스택 표·포트 표·실행 명령·알고리즘 설명 포함) 는 **README.md 와 위키로 해체**한다.

### 4.4 위키 유지 규칙

- 페이지가 200줄을 넘으면 쪼갠다.
- 결정이 뒤집히면 ADR 을 삭제하지 않고 `status: deprecated` + "대체: [[0012-...]]" 로 남긴다.
- 코드와 위키가 어긋나면 **위키가 틀린 것으로 간주**하고 즉시 고친다. 계약 페이지만 예외 — 계약과 코드가 다르면 **코드가 틀린 것**이다.

## 5장. 디자인 가이드 (요구사항 6) ★모바일 반응형 필수

### 5.1 시안에서 확정하는 것

**색**

| 토큰 | 용도 | 값(근사) |
|------|------|---------|
| `--color-primary` | CTA 버튼, 강조 숫자(D-day), 링크 | 인디고 `#3B4FD8` 계열 |

| `--color-surface` | 카드 배경 | `#FFFFFF` |
| `--color-bg` | 페이지 배경 | `#F7F8FC` |
| `--color-text` | 본문 | `#1A1D2E` |
| `--color-text-muted` | 보조 설명, 날짜 | `#6B7280` |
| `--shadow-card` | 카드 | 낮은 대비의 소프트 섀도우 |
| `--radius-card` | 카드 | `16px` |

아이콘 6타일은 파스텔 배경 + 채도 높은 글리프. 각 서비스에 고정 색을 배정한다(로또=그린, 통계=퍼플, 추천=오렌지, 꿈해몽=핑크, 뉴스=블루, 연금복권=그레이+"준비중" 배지).

**타이포** — 한글 가독성을 위해 Pretendard 를 기본 폰트로 채택한다(웹폰트 서브셋). 숫자는 `font-variant-numeric: tabular-nums` 로 자리 흔들림을 막는다.

**레이아웃 순서** (초안 6.1과 일치)
히어로 → 아이콘 6타일 → [최신 회차 결과 | 다음 추첨 D-day | 복권 뉴스] 3분할 → 주요 통계 4카드 → 오늘의 추천번호 캐러셀 → 로또 가이드 5카드 → 푸터

### 5.2 시안을 따르지 않는 것 — 번호 볼 색상

시안의 볼 색상(5=노랑, 11=초록, 18=파랑, 27=노랑, 33=초록, 42=회색)은 **동행복권 공식 5구간 규칙과 어긋난다.** 사용자가 다른 사이트에서 학습한 색-구간 매핑이 깨지면 신뢰도를 잃는다.

**공식 규칙을 채택한다.**

| 구간 | 색 |
|------|-----|
| 1~10 | 노랑 |
| 11~20 | 파랑 |
| 21~30 | 빨강 |
| 31~40 | 회색 |
| 41~45 | 초록 |

색만으로 구간을 전달하지 않는다(WCAG 1.4.1). 볼에는 항상 숫자가 있고, 스크린리더용 `aria-label` 에 "13번, 11~20 구간" 형태로 구간을 명시한다.

### 5.3 모바일 반응형 규약 ★

시안은 데스크톱 기준이다. 모바일 레이아웃은 아래를 **정식 사양**으로 삼는다. 모바일 트래픽이 로또 정보 검색의 다수를 차지하므로 **mobile-first 로 CSS 를 작성한다** — 기본 스타일이 모바일이고, `min-width` 미디어쿼리로 확장한다.

| 브레이크포인트 | 레이아웃 |
|---------------|---------|
| **~639px** (모바일) | 헤더 nav → 햄버거 드로어. 검색은 아이콘 → 전체화면 오버레이. 히어로 일러스트 숨김 또는 축소. 아이콘 6타일 → **3×2 그리드**. 3분할 → 세로 스택(결과 → D-day → 뉴스). 통계 4카드 → 1열. 추천 캐러셀 → 터치 스와이프 + `scroll-snap`. 가이드 5카드 → 1열 |
| **640~1023px** (태블릿) | 2열 그리드. 아이콘 6타일 → 3×2. 3분할 → 결과 전폭 + [D-day \| 뉴스] 2열 |
| **1024px~** (데스크톱) | 시안 그대로 |

추가 규칙:

- **터치 타겟 최소 44×44px.** 번호 볼, 캐러셀 화살표, "다시 생성" 버튼 모두 적용. 볼은 모바일에서도 최소 36px 지름 + 주변 패딩으로 44px 히트영역 확보.
- **모바일에서는 차트보다 요약 카드 우선** (초안 7.2). 번호 출현 빈도 막대차트(45개 막대)는 모바일에서 가독성이 없다. 모바일에서는 상위 5개 + "전체 보기" 링크로 축약하고, 전체 차트는 통계 상세 페이지에서 가로 스크롤 컨테이너로 제공한다.
- **CLS 방지** (Core Web Vitals, 초안 12.1). 볼·차트·뉴스 썸네일·광고 슬롯에 `aspect-ratio` 또는 `min-height` 를 미리 예약한다. 데이터가 늦게 도착해도 레이아웃이 밀리지 않아야 한다.
- **가로 스크롤 금지.** 페이지 `body` 는 절대 가로로 스크롤되지 않는다. 넓은 표·차트는 각자의 `overflow-x: auto` 컨테이너 안에서 스크롤한다.
- `prefers-reduced-motion: reduce` 존중. 캐러셀 자동 재생·볼 등장 애니메이션을 끈다.
- 다크모드: 시안 헤더에 토글이 있다. `prefers-color-scheme` 을 기본 신호로 쓰고 수동 토글이 이를 덮어쓴다.

## 6장. SEO / 애드센스 / 애널리틱스 (요구사항 11, 15)

초안 11·12장의 정책 기준을 Next.js 구현 사양으로 옮긴다.

### 6.1 렌더링 전략

| 페이지 | 방식 | revalidate |
|--------|------|-----------|
| `/`, `/lotto` | ISR | 추첨 후 갱신 (1시간) |
| `/lotto/round/{n}` | SSG + ISR | 과거 회차는 사실상 불변 → 긴 주기 |
| `/lotto/latest` | ISR | 짧게 (10분) |
| `/lotto/stat/*` | ISR | 주 1회 |
| `/news` | ISR | 수집 주기에 맞춤 |
| `/guide/*`, `/privacy`, `/terms` | SSG | 정적 |
| `/lotto/recommend`, `/dream` | SSG 셸 + 클라이언트 인터랙션 | 생성 결과는 CSR |

추천·꿈해몽은 결과가 매번 달라 SSR 이 무의미하다. 다만 **페이지 본문(설명·기준·면책·가이드)은 서버 렌더링**해야 검색엔진이 읽는다. 초안 4.1의 "아이콘만 있고 설명 본문이 없는 홈 화면"을 피하는 지점이 여기다.

### 6.2 메타데이터

- 각 라우트에 `generateMetadata` 로 고유 `title` / `description` / `canonical` / OG / Twitter.
- `app/sitemap.ts` 는 백엔드 `GET /api/meta/sitemap-entries` 를 호출해 회차·뉴스 URL 을 동적으로 채운다.
- `app/robots.ts`.
- JSON-LD: `Organization`, `WebSite`(사이트 검색), `BreadcrumbList`(전 페이지), `Article`(가이드·뉴스·꿈해몽), `Dataset`(통계 페이지), `FAQPage`(**실제 FAQ 가 화면에 보일 때만** — 초안 12.4).

### 6.3 검색엔진 등록

- **Google Search Console**: `GOOGLE_SITE_VERIFICATION` 메타태그를 `app/layout.tsx` 에 주입 → 사이트맵 제출.
- **네이버 서치어드바이저**: `NAVER_SITE_VERIFICATION` 메타태그로 소유확인 → 사이트맵·RSS 제출. 국내 검색 유입에 필수.

### 6.4 애널리틱스 (요구사항 15) ★함정 주의

측정 목표: 접속수, 유입 경로, 페이지별 체류시간.

- **GA4**: `접속수` = `page_view`, `유입` = `session_source` / `referrer`, `체류시간` = `user_engagement` 이벤트의 `engagement_time_msec`.
- **네이버 애널리틱스**: 스크립트 + 사이트 ID 삽입. 국내 유입 채널(네이버 검색·블로그) 분해에 유용.

> ⚠ **Next.js App Router 함정**: 클라이언트 사이드 라우팅이므로 `gtag` 기본 스니펫은 **최초 진입 시 한 번만** `page_view` 를 보낸다. 링크로 이동한 페이지는 집계되지 않는다.
> → `usePathname()` + `useSearchParams()` 를 구독하는 클라이언트 컴포넌트를 두고 경로 변경 시 `gtag('event', 'page_view', ...)` 를 **수동 전송**한다. 네이버 애널리틱스도 동일한 문제를 가지므로 같은 훅에서 함께 처리한다.
> 스크립트 로드는 `next/script` 의 `strategy="afterInteractive"` 를 쓴다. `beforeInteractive` 는 LCP 를 해친다.

### 6.5 애드센스

- **승인 전에는 광고를 넣지 않는다.** `NEXT_PUBLIC_ADSENSE_CLIENT` 가 비어 있으면 광고 컴포넌트가 아무것도 렌더링하지 않도록 설계한다.
- 신청 전 충족해야 할 콘텐츠 최소 기준은 초안 11.2 그대로 따른다(회차 상세 20+, 통계 3~5, 가이드 5~10, 꿈해몽 키워드 10+).
- 필수 정책 페이지 4종(`/privacy`, `/terms`, `/disclaimer`, `/contact`)을 MVP 에 포함한다 — 초안 11.1.
- `public/ads.txt` 는 승인 후 추가.
- 광고 슬롯은 `min-height` 를 예약해 CLS 를 만들지 않는다(5.3).
- "준비 중" 페이지(연금복권·스피또)에는 광고를 렌더링하지 않는다 — 초안 3장·17장.

## 7장. 세션별 작업지시

각 세션은 아래 포맷을 자기 `CLAUDE.md` 의 근거로 삼는다.

### 7.1 세션 A — `worker/` (워커)

**책임**: 외부 소스에서 데이터를 가져와 Postgres 에 쓴다. 그 외 아무것도 하지 않는다.

**소유**: `worker/**`, Alembic 마이그레이션, `lotto_draws`·`lotto_prize_tiers`·`news_articles`·`job_runs` 테이블의 스키마.

**절대 하지 않는 것**: HTML 렌더링, 예측 계산, 공개 API 제공.

**재사용 자산**: `backend/app/crawler.py`, `backend/app/naver_source.py`, `backend/app/scheduler.py`, `backend/scripts/seed_from_github.py`.

**신규 개발**

1. **잡 레지스트리** — 잡을 이름으로 등록하고 각자의 크론·락·로깅을 갖는다 (요구사항 14).

   | 잡 | 크론 (KST) | 근거 |
   |----|-----------|------|
   | `lotto` | 매주 토 21:00 | 추첨 20:45 직후. 실패 시 22:00·23:00 재시도 |
   | `news` | 매일 06:00 / 12:00 / 18:00 | 네이버 API 쿼터 여유 있게. 확정 전 쿼터 확인 필요 |

   크론 문자열은 `env.sample` 에서 주입한다(`LOTTO_CRON`, `NEWS_CRON`). 코드에 박지 않는다.

2. **잡별 독립 락.** 현재 `crawler.py` 는 전역 `asyncio.Lock` 하나를 쓴다. 잡이 둘 이상이 되면 로또 수집이 뉴스 수집을 막는다. **잡 이름별 락**으로 바꾼다.

3. **수동 트리거** (요구사항 14)

   ```
   POST /internal/jobs/{job_name}/run    → 202 Accepted, {run_id}
   GET  /internal/jobs/status            → 잡별 최근 실행 상태
   GET  /internal/health
   Header: X-Job-Key: <WORKER_JOB_KEY>
   ```

   - 이미 실행 중이면 `409 Conflict`.
   - `X-Job-Key` 불일치 시 `401`. **상수 시간 비교**(`secrets.compare_digest`)를 쓴다.
   - `127.0.0.1` 에 바인딩하고 nginx 에 노출하지 않는다. 원격 실행은 SSH 터널 또는 내부망으로.
   - 관리자 UI 는 만들지 않는다.

4. **`job_runs` 로깅** — 모든 실행(크론·수동)을 기록. `trigger` 컬럼으로 구분.

5. **네이버 뉴스 API 클라이언트** — 9장·13장의 사전 확인 완료 후 구현. 쿼터 초과 시 백오프, `link` UNIQUE 로 중복 방지. **원문을 복제하지 않는다** — 제목·요약·출처·발행일·링크만 저장 (초안 14.3).

6. **워커는 1 프로세스.** 락이 프로세스 내부이므로 다중 워커면 중복 실행된다.

**의존성**: `httpx`, `apscheduler`, `psycopg[binary]`, `alembic`, `fastapi`, `uvicorn`. **ML 라이브러리 없음** → Python 3.13 을 제약 없이 쓴다.

**완료 기준**: 빈 DB 에서 시드 → `lotto` 수동 트리거 → 최신 회차 1건 증분 수집 → `news` 수동 트리거 → 기사 N건 저장. `job_runs` 에 4행. 백엔드 없이 단독으로 검증 가능해야 한다.

### 7.2 세션 B — `backend/` (웹 API)

**책임**: Postgres 를 읽어 계산하고 JSON 으로 제공한다.

**소유**: `backend/**`, REST 계약의 구현.

**절대 하지 않는 것**: DB 쓰기, 스키마 마이그레이션, 외부 크롤링, 스케줄링.

**재사용 자산**: `app/prediction/**`(그대로), `app/dream/**`(그대로), `app/schemas.py`.

**신규 개발**

1. `DATABASE_URL` 은 **read-only 롤**(`app_reader`). 쓰기를 시도하면 DB 가 거부한다 — 실수를 코드리뷰가 아니라 권한으로 막는다.
2. `aiosqlite` → `psycopg` 비동기 풀로 교체.
3. 8장 API 계약 구현.
4. ChromaDB 는 `chroma_words` 디렉토리를 **읽기 전용**으로 연다. 모델(`upskyy/kf-deberta-multitask`) 은 lazy 싱글톤 유지 — 첫 요청 ~20초.
5. 무거운 numpy·임베딩 작업은 `asyncio.to_thread` 로 이벤트 루프를 막지 않는다.
6. 수동 트리거를 프록시하지 않는다. 백엔드는 워커의 존재를 모른다.

**Python 3.13 + torch 제약** (요구사항 9)

이 저장소는 과거 `torch 2.11` 이 Python 3.13 에서 `import torch` 시 JIT 오버로드 파서 크래시를 일으켜 `.python-version` 을 3.11 로 고정한 이력이 있다. **현재 `torch 2.13.0` 은 3.13/3.14 를 공식 지원 분류자에 포함한다.**

→ `pyproject.toml` 에 `torch>=2.13` 을 **명시적으로 하한 핀**하고, `requires-python = ">=3.13,<3.14"` 로 상한도 건다(상한이 없으면 `uv sync` 가 최신 인터프리터를 집어 재발한다). 첫 `uv sync` 직후 `uv run python -c "import torch; print(torch.__version__)"` 스모크 테스트를 **반드시** 통과시킨다. 실패하면 3.13 을 포기하고 백엔드만 3.12 로 내린다(워커·프론트는 영향 없음).

> venv 를 **절대 sudo 로 만들지 않는다.** 과거 `sudo uv sync` 로 만든 venv 의 인터프리터 심볼릭 링크가 `/root/` 아래를 가리켜 일반 사용자가 `uv run` 을 못 쓴 이력이 있다.

**완료 기준**: 워커가 채운 DB 에 대해 계약의 전 엔드포인트가 200 을 반환. 쓰기 시도 시 권한 오류. `sets=3&seed=1` 로 두 번 호출해 동일 결과(재현성).

## 8장. 공유 계약 초안 (Phase 0 에서 확정)

> 이 장은 `docs/wiki/10-contracts/` 로 옮겨지며, 그 순간부터 **위키가 정본**이다.

### 8.1 DB 스키마

```sql
CREATE TABLE lotto_draws (
    round_no            INTEGER PRIMARY KEY,
    draw_date           DATE        NOT NULL,
    num1, num2, num3, num4, num5, num6  SMALLINT NOT NULL,  -- 오름차순 저장
    bonus               SMALLINT    NOT NULL,
    total_sell_amount   BIGINT,          -- 네이버 소스에선 NULL
    first_win_amount    BIGINT,
    first_winner_count  INTEGER,
    first_accum_amount  BIGINT,          -- 네이버 소스에선 NULL
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 초안 8.1 "등위별 당첨자 수/당첨금" 요구. 현재 미수집 → 소스 확보 후 채움
CREATE TABLE lotto_prize_tiers (
    round_no        INTEGER REFERENCES lotto_draws(round_no) ON DELETE CASCADE,
    rank            SMALLINT NOT NULL CHECK (rank BETWEEN 1 AND 5),
    winner_count    INTEGER,
    prize_per_game  BIGINT,
    PRIMARY KEY (round_no, rank)
);

CREATE TABLE news_articles (
    id            BIGSERIAL PRIMARY KEY,
    title         TEXT        NOT NULL,
    description   TEXT,                    -- 네이버 API 요약. 원문 복제 아님
    link          TEXT        NOT NULL UNIQUE,
    orig_link     TEXT,
    source        TEXT        NOT NULL DEFAULT 'naver',
    pub_date      TIMESTAMPTZ,
    keywords      TEXT[],
    collected_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX ON news_articles (pub_date DESC);

CREATE TABLE job_runs (
    id               BIGSERIAL PRIMARY KEY,
    job_name         TEXT        NOT NULL,          -- 'lotto' | 'news'
    trigger          TEXT        NOT NULL,          -- 'cron' | 'manual'
    status           TEXT        NOT NULL,          -- 'running'|'success'|'failed'
    started_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
    finished_at      TIMESTAMPTZ,
    items_collected  INTEGER     NOT NULL DEFAULT 0,
    error_message    TEXT
);
CREATE INDEX ON job_runs (job_name, started_at DESC);
```

**롤 권한**

```sql
CREATE ROLE app_writer LOGIN PASSWORD :'writer_pw';   -- worker
CREATE ROLE app_reader LOGIN PASSWORD :'reader_pw';   -- backend

GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO app_writer;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO app_writer;

GRANT SELECT ON ALL TABLES IN SCHEMA public TO app_reader;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT ON TABLES TO app_reader;
```

`ALTER DEFAULT PRIVILEGES` 를 빠뜨리면 워커가 새 테이블을 만들 때마다 백엔드가 권한 오류를 낸다. 마이그레이션 직후 백엔드가 죽는 전형적인 원인이다.

### 8.2 백엔드 REST 계약

| Method | Path | 설명 |
|--------|------|-----|
| GET | `/health` | 헬스체크 |
| GET | `/api/lotto/latest` | 최신 회차 |
| GET | `/api/lotto/rounds?page=&size=` | 회차 목록 (size 최대 200) |
| GET | `/api/lotto/rounds/{round_no}` | 회차 상세 (없으면 404) |
| GET | `/api/lotto/stats/frequency?window=20\|50\|100\|all&include_bonus=` | 번호별 출현 빈도 |
| GET | `/api/lotto/stats/hot-cold?window=` | HOT / COLD / 미출현 기간 |
| GET | `/api/lotto/stats/pattern?window=` | 홀짝·고저·합계·연속·끝수·번호대 |

## 9장. 환경변수 / 시크릿 규약 (요구사항 5)

### 9.1 절대 규칙

1. **Claude 는 `.env` 를 읽지 않는다.** 어떤 이유로도. `cat`, `grep`, `Read` 전부 금지.
2. 환경변수 정보가 필요하면 **`env.sample` 을 읽는다.**
3. 새 변수가 필요하면 `env.sample` 에 **키 + 주석만** 추가하고, 사용자에게 `.env` 갱신을 요청한다. 값을 추측해 채우지 않는다.
4. `.env` 는 `.gitignore` 에 유지한다. `env.sample` 은 커밋한다.

### 9.2 컴포넌트별 분리

배포 시 컨테이너마다 다른 시크릿을 주입해야 하고, 프론트의 `NEXT_PUBLIC_*` 는 번들에 박혀 공개된다. 하나의 `.env` 를 공유하면 **읽기 전용이어야 할 백엔드가 쓰기 비밀번호를 갖게 된다.** 최소 권한 원칙에 어긋난다.

→ `worker/env.sample`, `backend/env.sample`, `frontend/env.sample` 로 나눈다. 루트 `env.sample` 은 공통값(사이트명·타임존)만 남긴다.

## 10장. 마이그레이션: SQLite → Postgres (요구사항 7)

1회성 스크립트 `worker/scripts/migrate_sqlite_to_pg.py`.

**절차**

1. `backend/data/lotto.db` 를 읽기 전용으로 연다 (`file:...?mode=ro`).
2. Alembic 으로 Postgres 스키마를 만든다.
3. `lotto_results` → `lotto_draws` 로 복사. 컬럼 매핑:
   - `draw_date` TEXT → DATE 캐스팅
   - `created_at` TEXT(KST ISO8601) → TIMESTAMPTZ (타임존 명시 주의: naive 문자열이면 KST 로 해석)
   - `num1..num6` INTEGER → SMALLINT
4. `crawl_logs` 는 이관하지 않는다 — `job_runs` 와 스키마가 다르고 이력 가치가 낮다. 필요하면 SQLite 파일을 보관.
5. `lotto_prize_tiers` 는 비운다 — 현재 등위별 데이터가 없다.

**검증 쿼리** (이관 성공 판정)

```sql
-- 행수 일치
SELECT count(*) FROM lotto_draws;                  -- SQLite 와 동일해야 함
-- 회차 연속성 (빠진 회차 탐지)
SELECT max(round_no) - min(round_no) + 1 = count(*) AS contiguous FROM lotto_draws;
-- 번호 정렬 불변식
SELECT count(*) FROM lotto_draws
 WHERE NOT (num1<num2 AND num2<num3 AND num3<num4 AND num4<num5 AND num5<num6);  -- 0 이어야 함
-- 번호 범위
SELECT count(*) FROM lotto_draws
 WHERE num1 < 1 OR num6 > 45 OR bonus < 1 OR bonus > 45;                         -- 0 이어야 함
```

**롤백**: 이관은 멱등이 아니다. 실패 시 `TRUNCATE lotto_draws CASCADE` 후 재실행. `lotto.db` 는 이관 후에도 삭제하지 않고 보관한다.

**ChromaDB 는 이관하지 않는다.** `backend/data/chroma_words/` 를 그대로 쓴다 — 4,802 단어 × 768 차원으로 용량이 작고, pgvector 를 도입하면 임베딩 재생성·인덱스 튜닝·모델 버전 관리가 따라붙는다. Postgres 는 관계형 데이터만 담당한다.

> 폐기되는 결정: 현행 `CLAUDE.md` 의 "WSL/NTFS 호환을 위해 `journal_mode=DELETE` 고정, 되돌리지 말 것" 은 SQLite 전용 제약이므로 Postgres 전환과 함께 무효가 된다. ADR 에 `deprecated` 로 기록한다.
