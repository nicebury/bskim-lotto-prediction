## 2장. 네 관점 분석 (002 §공통규칙 2)

### 2.1 기획 설계자 관점

이번 라운드의 본질은 **"기능 추가"가 아니라 "신뢰도·완성도 끌어올리기"** 다. 1차 오픈본은 기능은 갖췄지만 (a) 통계가 빈약해 보이고, (b) 가이드가 얇고 서로 중첩되며, (c) 뉴스가 목록 뿐이고, (d) 문구가 딱딱하다. 002의 요구는 전부 이 네 약점을 겨냥한다.

핵심 긴장: 이 사이트의 정체성은 **"당첨을 예측·주장하지 않는 정직한 재미용 도구"**(`forbidden-expressions.md`, `0007-site-name`) 다. 그런데 002는 "AI 로또번호 추천"·"주요통계 강화"처럼 **예측 마케팅으로 오인될 여지**가 있는 방향을 요청한다. 통계를 풍부하게 보여주되 그것이 "다음 회차 예측"이 아니라 "지난 사실의 정리"임을 UI가 스스로 말하게 해야 한다. 인사이트 콜아웃·팝업 톤·면책 문구가 그 방어선이다.

### 2.2 UI/UX 디자이너 관점

- **일관성이 최우선(R35).** 페이지마다 다른 카드·간격·아이콘을 쓰면 아마추어처럼 보인다. 모든 변경은 기존 디자인 토큰(`tokens.css`)과 `components.css` 클래스를 재사용하고, 새 원시값(hex·px)을 흩뿌리지 않는다.
- **주요통계(R8)** 는 정보 밀도가 급증한다. 40대+ 사용자가 표를 읽을 수 있게 **숫자 정렬(tabular-nums)**, 충분한 행 높이, 추세 화살표는 **색+기호 동시**(색맹 대비, WCAG 1.4.1)로 표현한다.
- **아이콘 통일(R13/R32)** 은 "제각각"을 없애는 대표적 정돈. 모양은 하나, 색만 팔레트에서 결정론적으로 배정한다.
- **이미지(R14/R34)** 는 "남발 금지"가 핵심. 가이드 페이지당 1~2장, 본문 흐름을 돕는 위치에만. 장식용 과다 이미지는 전문성을 오히려 떨어뜨린다.

### 2.3 사이트 사용자 관점 (40대 이상 염두)

- **글자·터치 타깃이 커야 한다.** 네비 폰트 2pt 확대(R5)는 이 맥락에서 정당하다. 볼·버튼은 이미 44px 규약(`responsive-rules.md`)을 따른다.
- **모바일에서 가로 스크롤은 발견성이 낮다(R12).** 40대+는 옆으로 숨은 카드를 잘 못 찾는다. 세로 나열이 스캔에 유리.
- **문구는 친절해야 한다(R11).** "유일한 정직함" 같은 표현은 의도는 좋으나 훈계처럼 읽힌다. "함께 즐기는 도구"의 어조로.
- **가이드는 "검색으로 들어온 사람"이 독자다.** 동행복권 사이트/네이버 검색 안내(R18), 상세조회 링크(R20)처럼 **실제 행동으로 이어지는 안내**가 유용.

### 2.4 개발자 관점

- **워커는 이번 라운드에서 건드릴 게 없다**(3·4장). 뉴스 원천(`keyword_list`·`published_dttm`)과 회차 원천(`lotto_draw`)이 이미 저장돼 있어, 통계 재구성·동반출현·뉴스 조회조건은 전부 **백엔드 조회 시 계산**으로 해결된다. 통계 테이블 미보유 결정(`db-schema.md`, `log 2026-07-10`)을 유지한다.
- **백엔드 변경은 전부 계약(`api-contract.md`) 변경**이다 → 세 세션 영향이 있으니 위키를 먼저 고친다.
- **프론트가 작업의 대부분**이다. 백엔드 신규 필드에 의존하는 부분(주요통계·동반출현·뉴스 조회)은 계약이 얼어야 안전하게 착수 가능.

### 3.1 Footer (R1~R4)

- **현재**: `components/Footer.tsx:73-77` 면책 문구가 한 개 `<p>` 안에 통짜 평문. `.footer-disclaimer`(`components.css:1973`)는 muted 색·기본 굵기뿐.
- **변경**: 문구를 의미 단위로 분할해 (R2) "19세 미만…" 을 별도 줄, (R3) "참고용·재미용 시뮬레이션" 에 색상(`--color-primary` 또는 주의색), (R4) "당첨을 보장하지 않으며…" 를 `<strong>`.
- **설계근거**: 면책은 법적·정책적 방어선(`forbidden-expressions.md` 면책 부착 위치)이라 눈에 띄어야 한다. 단, 톤이 과하면 불안감을 준다 → 색은 1곳, 볼드는 1곳으로 절제.
- **구현안**: 문구를 `<span>` 조각으로 나누고 `.footer-disclaimer-accent`(색)·`<strong>`·`<br/>` 또는 별도 `<p>`. 새 색은 토큰 재사용.

### 3.2 페이지 네비게이션 (R5~R6)

- **현재**: `.header-nav a`(`components.css:250`) `font-size: var(--fs-body)`(0.95rem)·`--fw-medium`(500). active(`:267`)는 `--fw-semibold`(600)+primary 색.
- **변경**: (R5) 폰트 약 2pt(≈0.13rem) 상향, (R6) active 를 `--fw-bold`(700).
- **설계근거**: 40대+ 가독성(2.3). "2pt"는 절대치라 rem 환산(브라우저 기본 16px 기준 2pt≈0.167rem, 실무상 `--fs-body` 0.95rem → 약 1.08rem)으로 반영하고 토큰화 검토.
- **구현안**: `--fs-body` 를 건드리면 전역 파급 → 네비 전용 규칙에서만 상향. active `font-weight` 를 700으로.

### 3.3 히어로 CTA (R7)

- **현재**: `app/page.tsx:73-80` 2버튼 = "최신 로또 결과 보기"(→`/lotto/latest`) + "번호 추천 시뮬레이션"(→`/lotto/recommend`). "꿈으로 번호찾기" 버튼 없음.
- **변경**: 2버튼 = `AI 번호 조합 추천`(→`/lotto/recommend`, primary) + `꿈으로 번호찾기`(→`/dream`, secondary). "최신 결과 보기" 제거.
- **설계근거**: 6장 결정. 최신 회차는 하단 결과 카드·네비로 접근 가능하므로 히어로에서 빼도 유입 손실이 작다. 'AI' 는 예측 오인을 줄이려 "번호 **조합** 추천"으로 조정(사이트가 이미 쓰는 '조합 성향' 언어와 정합).
- **구현안**: `hero-cta` 두 링크 라벨·경로·순서 교체. 꿈해몽 경로(`/dream`)는 네비(`lib/site.ts`)에서 확인.

### 3.4 주요통계 재구성 (R8~R10) ★가장 큰 작업

## 4장. 세션별 작업 분류 ★핵심

세 세션은 **병렬·독립**으로 돈다. 아래 분류와 의존을 지킨다.

### 4.1 세션 A — worker: **변경 없음**

002의 어떤 요구도 워커 수집을 바꾸지 않는다. 뉴스는 이미 네이버 API로 수집되고 `keyword_list`·`published_dttm` 가 저장돼 있으며, 회차 원천 `lotto_draw` 도 완비됐다. 통계 재구성·동반출현·뉴스 조회조건은 전부 백엔드 조회 시 계산으로 해결된다.
→ **워커 세션은 이번 라운드에 기동할 필요가 없다.** (통계 테이블 미보유 결정 유지.)

### 4.2 세션 B — backend: 계약 변경 3건

| ID | 작업 | 대상 | 관련 R |
|----|------|------|--------|
| **B1** | 통계 응답에 신규 필드 추가: **출현 비율**(`count/rounds_analyzed`), **최근 출현 회차**(번호별 마지막 등장 `round_no`), **추세**(단기 vs 장기 window 빈도 비교 → up/down/flat). `hot-cold`·`frequency` 응답 확장 | `routers/stats.py`, `domain/stats.py`, `schemas.py` | R8·R10 |

## 7장. 사용자 확인 항목 (해소 완료)

7장 4건은 사용자 답변으로 **모두 해소됐다**(2026-07-15).

- [x] **`PEXELS_API_KEY`** — 실제 값은 사용자가 `frontend/.env_frontend` 에 넣음. `frontend/env.sample` 에는 키+주석만 추가했다(`NEXT_PUBLIC_` 미부착 = 서버 전용). 사용 방식은 [[pexels-image-usage]].
- [x] **이미지 저작권·검수** — 최종 이미지는 **사용자가 다 만든 뒤 직접 검수**한다. **실제 사람을 쓰지 않고**, 상업·비상업 사용 가능한 것만 쓴다. 필요한 이미지는 **AI 생성용 요청서** [`002-이미지제작요청서.md`](./002-이미지제작요청서.md) 에 복붙용 영문 프롬프트·저장경로·파일명으로 정리했다. Pexels License 사실 정리는 [[pexels-image-usage]] 에 둔다(법률 판단은 사용자 몫).
- [x] **'AI' 라벨** — `AI 번호 조합 추천` 채택(예측 뉘앙스 약화 + 사이트의 '조합' 언어와 정합). 필요 시 사용자가 언제든 문구 조정 가능.
- [x] **추첨 시각 문구** — "매주 토요일 **오후 8시 35분경**"(위키 KST 20:35~20:45, 방송 시작 기준) 채택. [[lotto-rules]] 에 사용자 노출 문구로 명문화.

### 이미지 방침 (확정)

- 시각 언어 일관성(R35)을 위해 **가이드 상세 이미지는 브랜드 팔레트 플랫 일러스트(AI 생성)로 통일**하는 것을 1순위로 한다. Pexels 실사는 꼭 필요한 경우의 대안이며, **인물 사진은 쓰지 않는다**.
- **등수 판정 시각화(R19)** 는 정지 이미지가 아니라 **기존 `LottoBall` 컴포넌트**로 그린다 — 공식 색 규칙·다크모드·접근성을 자동으로 따른다.
- 상세는 [`002-이미지제작요청서.md`](./002-이미지제작요청서.md).
